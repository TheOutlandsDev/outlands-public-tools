# Four independent intake and parser tools

This pass adds four source-only tools with separate CLI/library interfaces,
fictional examples, tests, source manifests and MIT licenses:

| Tool | Scope |
| --- | --- |
| [Workbook & CSV Intake Checker](../tools/workbook-intake-checker/README.md) | Explicit typed mapping, limited XLSX/CSV previews, duplicate/conflict/rejection accounting |
| [Snapshot Contract Checker](../tools/snapshot-contract-checker/README.md) | Supplied file byte pins, version/freshness declarations and declared count reconciliation |
| [XML Workflow Checker](../tools/xml-workflow-checker/README.md) | Invented forward/rework graph schema, reference checks and revision comparison |
| [Planner Input Handoff Checker](../tools/planner-handoff-checker/README.md) | Exact project/evidence review pins and actual existing public planner contract/calculation checks |

The interfaces remain independent. There is no combined browser application,
new distribution package or change to the immutable Toolkit 0.6.0 assets.
Catalog family labels are navigation metadata; these four additions are explicitly
source-only/pending packaging. Future assembly follows the remaining source audit
and the user's additional list. No Site is changed by this source publication.

## Public/private boundary

Fresh generic implementations, invented contracts and fictional fixtures. The
Windows backend and selected planner models/engines come only from already-public
source, with exact origin pins in each tool's guide. No private original code,
business mapping/formula/schema, customer/user data, endpoint, deployment identity,
credential, document, workbook, asset or operational instance is selected.
Original applications are not modified, imported or executed. Whole-family and
whole-drive clearance remains incomplete; presence in a private inventory does
not grant publication clearance.

The XLSX parser uses a strict plain-cell subset and never extracts the archive,
evaluates formulas or invokes Office. Snapshot count reconciliation is arithmetic
over declarations, not an independent record count. Workflow graphs use a fresh
schema, not an original recipe or operational route. Planner handoff uses the
public parser/calculation path without stores, imports or target writes. Checkboxes
and hash pins are caller assertions, not authenticated organizational approval.

## Qualification boundary

[The qualification workflow](../.github/workflows/intake-parser-tools-checks.yml)
runs Windows/Ubuntu with Python 3.12/3.13, hash-pinned planner dependencies, all four
unit suites and source checks, native linked-path/hardlink refusals, actual
standalone CLI copies, generated fictional XLSX/CSV parity, new-only reports,
and a four-tool reviewed-evidence walkthrough. Native fixture creation is required
in CI. Only opposite-platform methods may be skipped there.

The integrated walkthrough preserves the explicitly selected public fictional
planner project, attaches the intake/snapshot/workflow results, withholds incomplete
review, accepts explicit matching review and invalidates it after evidence tamper.
It never infers production mappings from those reports or creates a planner store.
Exact staged sources and public-source copies are audited before publication.
Private audit reports, detailed inventory paths, test outputs and failure evidence
remain outside the repository. Public source pins do not replace authenticity or
rights review. See each tool's validation and I/O guide for unsupported conditions.
