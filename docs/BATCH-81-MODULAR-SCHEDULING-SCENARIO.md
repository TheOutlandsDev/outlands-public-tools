# Batch 81 - Independent scheduling and scenario integrity tools

Four fresh generic MIT tools inspect invented HVAC assembly/inspection task plans and
game-build working windows. [Example themes](FICTIONAL-EXAMPLE-THEMES.md) remain HVAC,
AI and game development. Original private implementations, schemas, calendars, policies,
schedules, records, paths, credentials and operating details were not consulted or
selected. Original-family and whole-drive clearance remain incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [Availability Exception Planner](../tools/availability-exception-planner/README.md) | Pinned working windows minus declared closure unions | No real calendar updates or availability proof |
| [Task Precedence Checker](../tools/task-precedence-checker/README.md) | Full task DAG, required lags and precedence-only lower bounds | No capacity/calendar feasibility or optimization |
| [Schedule Timing Checker](../tools/schedule-timing-checker/README.md) | Proposed placements, releases, due values, windows and lags | No capacity check, rescheduling or dispatch |
| [Schedule Scenario Comparator](../tools/schedule-scenario-comparator/README.md) | Comparable per-task and whole-cohort deltas with visible gaps | No hidden scope omission, ranking or preferred plan |

Each complete directory runs independently with Python 3.12/3.13 standard library.
Public MIT I/O/identity helpers have exact provenance pins; scheduling logic is fresh.
Strict schemas, complete identity accounting and full snapshot/cohort pins prevent
silent latest/best proposal selection. Invalid graphs/references withhold assessments;
logical timing findings remain visible without qualified scope pins. Calendar/closure
expansion limits prevent unbounded missing/fragmented-window report growth.

Native tests require hardlink, linked-parent, changed-input, fresh-file and overwrite
fixtures. Actual connected CLI acceptance checks invented closure subtraction, DAG
lower bounds, proposed placements and a complete candidate comparison. Missing tasks
block aggregate deltas. A separate explicit adapter calls the existing public resource
reservation checker for one-unit capacity and overlapping-reservation counterexamples;
the new tools do not duplicate that engine or claim capacity checking. No real schedules,
calendar accounts, resources, assets or commands are used.

Existing systems, packages, downloads, workshops, theme guide and root README remain
unchanged by this pass. The generated three starting workflows and prior announcement
index are preserved; a new linked announcement follows the index in the changelog.
New modules stay outside the frozen package plan; combined packaging remains deferred.
Keep actual plans/reports private. These checks do not prove physical feasibility,
complete constraints, authentic durations, optimization, privacy or dispatch authority.
