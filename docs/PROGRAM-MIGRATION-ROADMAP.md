# Whole-program publication roadmap

The [Offline ML Experiment & Evaluation Workbench](../systems/ml-experiment-workbench/README.md) adds a complete fresh tabular learning/evaluation app with explicit temporal/group boundaries, immutable experiments, train-only fitting, artifact review and private exports. Generated records and actual Chromium acceptance exercise the selected implementation. Original operating source/data, feature mappings, configurations and models remain private and uncleared.

The [Visual Dataset & Annotation Workbench](../systems/visual-annotation-workbench/README.md) adds a complete fresh canvas/CLI application for independent regions, immutable review, grouped specimen splits and checked image/mask exports. Generated pixels and actual Chromium acceptance exercise the selected implementation. Original images, labels, models, operating source/configuration and unrelated families remain private and uncleared.

This collection is the shared home for reusable first-party applications,
systems and methods. Owner-confirmed source can retain its actual implementation
after review; releases should be coherent program families with usable interfaces,
documentation, fictional workflows and tests. Small conceptual utilities remain
useful building blocks, but do not substitute for reviewing a complete program.

## Repeatable release process

1. Inventory source only, record exclusions locally and choose a canonical program
   rather than copying archives and duplicate environments. Keep the real drive
   mapping and audit ledger private.
2. Separate first-party implementation from instance configuration, data,
   credentials, runtime assets and third-party code. Preserve required notices.
3. Retain the useful algorithms and interface. Replace historical bindings with
   explicit private workspaces, neutral contracts and invented example inputs.
4. Exercise full workflows and failure paths on Windows/Ubuntu where applicable.
   Record platform/runtime limits without implying unperformed validation.
5. Inspect the exact selected Git blobs and focused source archive. Review
   findings manually; never weaken a scanner simply to obtain a clean result.
6. Publish a coherent reviewed commit and focused source release, verify remote
   bytes and update the private per-program ledger. Leave incomplete families
   pending; prior publication never clears unrelated source or runtime data.

The roadmap does not publish source locations, actual project inventories,
customer names, deployment topology or operational audit records. It is a
publication method and queue, not a claim that every program is already cleared.
