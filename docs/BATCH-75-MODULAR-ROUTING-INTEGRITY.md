# Batch 75 - Independent AI routing and inference integrity tools

Four fresh generic MIT modules use newly invented HVAC request/model/fallback metadata
and a game NPC routing example. [Example themes](FICTIONAL-EXAMPLE-THEMES.md) remain
HVAC, AI and game development. Original private code, schemas, routing policies,
prompts, payloads, models, customer/user records, credentials, private paths, provider
endpoints and operational configuration were not consulted or selected. Original-family
and whole-drive clearance remain incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [Model Capability Contract Checker](../tools/model-capability-checker/README.md) | Explicit capability/type declarations and internal budget ceilings | No real model support, availability or measurement |
| [Request Routing Plan Checker](../tools/request-routing-checker/README.md) | Exact assignments, revisions, pins and declared eligibility limits | Manual review only; no model choice or dispatch |
| [Fallback Chain Contract Checker](../tools/fallback-chain-checker/README.md) | Complete bounded pointer chains and explicit failure conditions | No pruning, implicit retries, backoff or provider calls |
| [Inference Receipt Reconciler](../tools/inference-receipt-reconciler/README.md) | Recomputed fallback scope, ordered attempt receipts and terminal claims | Consistency does not prove inference occurrence or output truth |

Each complete directory runs independently with Python 3.12/3.13 standard library.
Native I/O and identity/fraction helpers are pinned public MIT copies. Routing logic
is fresh. Identical identity snapshots count once; conflicting groups withhold every
member. Invalid references/coverage/order withhold qualified results. Valid eligibility
failures and declaration mismatches retain full diagnostics. Missing fallback evidence
remains unknown, and a consistent terminal failure is not relabeled success.

The native matrix checks source pins, adversarial known results, required filesystem
fixtures, independent copies and actual connected CLIs. An invented HVAC flow checks
two capability declarations, one explicit assignment and a two-step fallback, then
reconciles a supplied primary timeout and reserve success. Neither model is invoked.
The game fixture remains hypothetical. Counterexamples distinguish internal capability
consistency from request eligibility and receipt consistency from actual inference.

These additions remain outside the frozen package plan. Existing systems, packages,
downloads, workshops and theme guide are unchanged. No combined application or new
release assets are created. Keep actual inputs/reports private: declaration consistency
does not establish authentic capabilities, measured units, true outputs, privacy, rights
or authorization to dispatch, publish, train or deploy.
