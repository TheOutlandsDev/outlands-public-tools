# Batch 85 - Independent access policy integrity tools

Four fresh generic MIT modules use invented HVAC service proposals, video-game release
policies and AI/software candidate-review scenarios. [Example themes](FICTIONAL-EXAMPLE-THEMES.md)
explicitly include AI/software; HVAC remains the manufacturing/service default. Original
private code, schemas, access policies, customer/user records, paths, credentials,
addresses and deployment details were not consulted or selected. Audit filename/ledger
entries support scope only; original-family/whole-drive clearance remain incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [Role & Permission Contract Checker](../tools/role-permission-contract-checker/README.md) | Exact literal declarations and bounded role inheritance | No real identities, directory discovery or safe-policy certification |
| [Access Decision Evaluator](../tools/access-decision-evaluator/README.md) | Supplied symbolic requests, default deny and deny precedence | No real authorization, enforcement or unrequested-scenario coverage |
| [Separation of Duties Checker](../tools/separation-of-duties-checker/README.md) | Explicit prohibited role/action pairs and selected workflow claims | No real actor authentication or complete action-history proof |
| [Access Policy Scenario Comparator](../tools/access-policy-scenario-comparator/README.md) | Exact comparable request cohorts across two declared policies | No whole-policy equivalence, security ranking or deployment |

Complete independent Python 3.12/3.13 standard-library directories share pinned public
MIT JSON/I/O/identity helpers; access-policy logic is fresh. Role/action/resource IDs
are literal, with no wildcard/expression semantics. Unknown action/resource references,
cycles and alias/conflicting identities withhold complete assessments and scope pins.
Expected-answer mismatches, duty conflicts and missing/changed comparison scenarios
retain diagnostics without qualified scope. Missing scenarios never imply improvement.
All policies, assignments, requests and action claims remain unverified declarations.

Native filesystem checks, strict JSON boundaries, adversarial known answers, standalone
copies and actual connected CLI acceptance qualify fictional inputs on Windows/Ubuntu.
A separate existing Approval Scope Checker adapter demonstrates that same-actor role
coverage can satisfy its contract while explicit separation-of-duties constraints flag
the same fictional actor's incompatible roles/actions. Its engine is not duplicated.

The root README, three starting workflows, existing systems/packages/downloads/workshops
and all prior source announcements are preserved. A new announcement follows the index.
The theme guide explicitly permits software examples; existing pinned examples keep
their provenance. New tools remain outside the frozen package plan; packaging is
deferred. No authentication, network probing, permissions/accounts changes or real
actions occur. Actual inputs/reports remain private; hashes are not anonymization.
