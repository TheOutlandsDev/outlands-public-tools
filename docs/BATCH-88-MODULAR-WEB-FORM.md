# Batch 88 - Independent web form and interaction integrity tools

Four fresh generic MIT modules use invented HVAC service-request review, game-build
forms and AI/software evaluation submissions. [Example themes](FICTIONAL-EXAMPLE-THEMES.md)
remain HVAC, video games and AI/software. Remaining web-application audit entries inform
scope only. Original code, forms/rules, policies, user/customer records, private paths,
credentials, deployment, operational data and assets were not consulted or selected.

| Independent tool | Scope |
| --- | --- |
| [Form Definition Contract Checker](../tools/form-definition-contract-checker/README.md) | Typed scalar fields and acyclic visibility/requiredness dependencies |
| [Form Submission Contract Checker](../tools/form-submission-contract-checker/README.md) | Exact form bindings and supplied values, including hidden-field refusal |
| [UI Transition History Checker](../tools/ui-transition-history-checker/README.md) | Exact flow/submission bindings and ordered state/action histories |
| [UI Interaction Scenario Comparator](../tools/ui-interaction-scenario-comparator/README.md) | Identical supplied observations under two complete contract versions |

Dependency cycles, ambiguous transitions, malformed components and stale references
withhold complete assessments. Value types are exact; unknown/hidden values are never
silently accepted or discarded. An invalid history stops state advancement at its first
bad step. Missing/changed observations remain incomparable. Reports omit scalar values
and unknown names while retaining bounded IDs, decisions, counts and hashes.

Submission validity, history validity and scenario equality are distinct. A declared
invalid-submission branch can be a valid history. Equal expected-negative comparisons
can pass without valid submissions/histories. No whole-UI compatibility claim follows.
Every complete directory runs independently with Python 3.12/3.13 standard library.
Public MIT JSON/I/O/identity helpers are pinned; conditional/history logic is fresh.

Windows/Ubuntu native boundaries, known answers, adversarial cases, independent copies
and connected fictional CLI acceptance qualify supplied declarations. An explicit
collection-only scalar projection exercises the existing Configuration Contract Checker.
This does not establish conditional UI semantics, real browser behavior or accessibility.
No HTML/DOM inspection, browser/script execution, network, authentication or target writes.
