# Batch 69 - Independent material and lot integrity tools

Four fresh generic MIT modules use [fictional HVAC examples](FICTIONAL-EXAMPLE-THEMES.md).
Original private implementations, schemas, product identifiers, customer records,
equipment designs, policies, configurations, paths, credentials and assets were not
consulted or selected. Original programs/files remain untouched; whole-drive and
original-family clearance remains incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [BOM Contract Checker](../tools/bom-contract-checker/README.md) | Explicit component DAG and exact bounded requirements | No equipment sizing, compatibility or orders |
| [Lot Identity & Alias Checker](../tools/lot-identity-checker/README.md) | Explicit canonical/alias chains and stock counted once | No physical identity proof or inferred aliases |
| [Material Allocation Coverage Checker](../tools/material-allocation-checker/README.md) | Demands and canonical-lot reservation arithmetic | No allocation selection, stock truth or reservation changes |
| [Handoff Lifecycle Checker](../tools/handoff-lifecycle-checker/README.md) | Complete declared histories and exact receipt references | No delivery proof, stock coverage or transfers |

Each complete directory runs independently with Python 3.12/3.13 standard library.
Native Windows/POSIX I/O guards are pinned existing public MIT source. Identical
identity snapshots count once; conflicting groups withhold every member. Invalid
structure/references/history withhold the complete tool result. Valid scoped
allocation shortages/excess/overreservation retain full diagnostics for review.

The dedicated four-platform matrix checks known results, mandatory native fixtures,
standalone copies and actual connected CLIs. Two fictional air-handler kits declare
two motors/four filters; motor labels resolve to one lot, reservations leave two
motors/four filters, and a separate invented two-motor service-bench receipt is
validated. A consistent receipt cannot override inventory shortfall. There is no
automatic connection between these tools and no live system access.

These additions remain independent source tools outside the existing frozen package
plan. Prior systems, workshops, downloads and package definitions are unchanged.
No combined workbench, runtime package or new release assets are created here.
Actual IDs, quantities, declarations and reports remain private; PASS is not rights
clearance, independently verified claims or operational approval.
