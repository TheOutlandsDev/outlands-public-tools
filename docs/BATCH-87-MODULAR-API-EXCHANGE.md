# Batch 87 - Independent API exchange integrity tools

Four fresh generic MIT tools use invented HVAC service-proposal previews, game-build
operations and AI/software evaluation requests. [Example themes](FICTIONAL-EXAMPLE-THEMES.md)
remain HVAC, video games and AI/software. Original private code, schemas, routes,
traffic/payloads, policies, customer/user records, paths, credentials, addresses and
deployment details were not consulted or selected. Audit filename/ledger entries
support scope only; original-family/whole-drive clearance remain incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [API Operation Contract Checker](../tools/api-operation-contract-checker/README.md) | Bounded literal/parameter routes, field rules and response variants | No full HTTP/OpenAPI/JSON Schema support or server existence proof |
| [API Request Contract Checker](../tools/api-request-contract-checker/README.md) | Structured observed method/path/media/parameters/body under exact operation pins | No wire decoding, requests, identity or authentication |
| [API Response Contract Checker](../tools/api-response-contract-checker/README.md) | Exact request bindings, response variants and declared observation coverage | No live responses or real service behavior proof |
| [API Exchange Scenario Comparator](../tools/api-exchange-scenario-comparator/README.md) | Identical observed scenarios under two compiled contract versions | No whole-API compatibility, security ranking or deployment |

Each complete directory runs independently with Python 3.12/3.13 standard library.
Public MIT JSON/I/O/identity helpers are byte-pinned; exchange logic is fresh. All
references bind normalized complete snapshots. Route overlaps, nested identity/slot
ambiguity and stale references withhold complete assessments. Optional absence never
inserts defaults; scalar types are exact. Diagnostics omit payload values and unknown
field names while retaining failure codes/field IDs. Hashes are not anonymization.

Request validity, response validity and scenario equality are distinct. A declared
error variant may be a valid response to an invalid request. Comparable expected-negative
cases can satisfy scenario equality without becoming valid traffic. Missing/changed
request or response observations never imply compatibility. All expectations are
caller assertions; no wire traffic or service state is observed.

Native filesystem tests, known answers/adversarial cases, standalone copies and actual
connected CLI acceptance qualify fictional data on Windows/Ubuntu. A separate explicit
adapter calls the public Configuration Contract Checker for invented flat body values
and out-of-range refusal; its engine is not duplicated. No clients, servers, endpoint
probes, authentication, model calls or target changes run.

Root README, three starting workflows, theme guide, existing systems/packages/downloads/
workshops and all prior source announcements remain unchanged by this pass. A new
announcement follows the changelog index. Modules stay outside the frozen package
plan; packaging remains deferred. Actual inputs/reports stay private. No real traffic,
wire compatibility, authentication, production readiness, privacy or rights are established.
