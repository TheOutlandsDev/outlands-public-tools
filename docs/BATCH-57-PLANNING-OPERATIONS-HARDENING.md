# Batch 57: Planning and Operations browser hardening

Harden the existing public [Production Planning](../systems/production-planning-workbench/README.md)
and [Operations Analytics](../systems/operations-analytics-workbench/README.md)
applications in one pass, preserving their calculation engines, data contracts,
append-only schemas, original tests, Windows/POSIX file guards and plan-only behavior.

Both browsers gain coherent snapshots, draft/discard boundaries, serialized actions,
revision-pinned reports, uncertainty without replay, nonce scripts and responsive
keyboard-accessible tables. HTTP operations are serialized and reject ambiguous
headers, framing and queries. Actual CLI shutdown/reopen and a Windows junction
fixture supplement prior lifecycle/native checks.

Required Windows/Ubuntu Python 3.12/3.13 qualification includes 86 planning core/HTTP
methods plus 19 Chromium methods, and 89 analytics core/HTTP methods plus 25 Chromium
methods. All applicable native fixtures are mandatory. The analytics suite generates
and stops a real fictional planning instance, copies only its five report files,
checks the browser handoff and rejects byte/inventory/rehashed authority/conservation
tampering without revisions or automatic eligibility/state mapping.

Existing public source and new neutral code/tests only: no private original code,
business mappings, customer/user records, deployment paths, credentials, logs,
configuration, browser state or assets are selected. Separate deterministic focused
source ZIPs retain MIT and dependency notices. Runtime records and reports remain
private. This does not clear any remaining original source family or historical data.

Real process/production suitability, shipping evidence, reviewer authenticity,
remote/multiuser hosting, hostile storage, power-loss recovery and damaged-store
restoration remain unverified. See each application's validation document.
