authentication into a fresh private directory. Their lengths and SHA-256 values
matched the previously verified release pins. The downloaded checksum file
matched the ZIP and external source manifest. ZIP integrity, exact member list,
member lengths and every content hash passed for all 194 selected source files.

## Workflows exercised

All inputs were authored fictional fixtures. Stores, reports, dependency
environments and generated outputs stayed in private scratch locations. The
original 194 extracted source files remained byte-for-byte unchanged.

| Group | Completed checks | Result and practical limits |
| --- | --- | --- |
| Portable standard-library workflows | 17 CLI/API scenarios | 10 successes and 7 expected findings/refusals; four refusals were the documented Windows guards in the POSIX-only editions |
| Portfolio Builder and Job & Quote Tracker | 30 CLI commands and 20 independent assertions | Exact portfolio dependency pins installed in an isolated environment; exports, refusal cases, fictional revisions/decisions, reports, backups and recovery matched their contracts |
| Remaining utility examples | 26 completed CLI invocations | 23 exit-zero results and 3 expected findings/refusals; DOCX, pinned source packaging, opaque transfer, maintenance/preflight, passive wake help/version, ELF examples and one disposable file move/restore |
| Local Site Builder | 17 setup, HTTP and recovery steps | Local login/CSRF, draft/publish isolation, stopped backup, verification, restore, export and restored state passed; loopback only, email disabled |

The runtime was Windows with Python 3.12.7 and Node 24.15.0/npm 11.12.1.
Document Builder used installed python-docx 1.2.0. Portfolio's separate environment
installed ReportLab 5.1.0, Pillow 13.0.0 and charset-normalizer 3.5.2. Site Builder's
declared `npm ci` completed with 86 packages and the existing native toolchain.

The first Site Builder install was blocked by the execution sandbox's Windows
SDK registry restriction; normal local access completed the same isolated
install. Likewise, the sandbox denied strict destination canonicalization for
File Mover; the identical plan passed with normal local access before its
fictional move/restore flow. No canonicalization or other security check was
removed to obtain a pass. These were runner restrictions, not demonstrated
application defects.

## Documentation corrections

- Replace the stale Package Layout Checker licensing sentence with the current
  selected-source MIT grant.
- Make the default collection quick start a portable read-only command and
  identify the three POSIX-only editions precisely.
- Use a shared [private workspace](PRIVATE-WORKSPACE.md) for generated examples,
  stores, reports, state and backups. Relative sibling paths inside the
  collection could otherwise put private material under `tools`.
- Clarify Site Builder's intentional private `.env` location and external data
  root, and refresh the application source manifests after documentation edits.

No runtime-code defect was identified in these completed workflows. This is
bounded example evidence, not full platform or production acceptance. In
particular, the one-file Windows mover case does not qualify alternate streams,
SMB, ACLs, hostile concurrency or power loss. Source Inventory's small Windows
fixture does not establish general Windows coverage. Native Keep Awake requests,
Tk/browser interaction, Word rendering, actual devices/firmware, real customer
records and live game/server operation were not exercised. Site Builder was
checked through its loopback HTTP interface, not a browser interaction test.
