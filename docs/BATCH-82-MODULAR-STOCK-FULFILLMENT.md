# Batch 82 - Independent stock and fulfillment integrity tools

Four fresh generic MIT modules use invented HVAC filters/stock/order declarations
and a game crafting-token ledger. [Example themes](FICTIONAL-EXAMPLE-THEMES.md) remain
HVAC, AI and game development. Original private implementations, schemas, policies,
records, documents, paths, credentials, addresses and operating details were not
consulted or selected. Original-family and whole-drive clearance remain incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [Stock Movement Ledger Checker](../tools/stock-movement-ledger-checker/README.md) | Opening balances and ordered receipt/issue/adjustment claims | No physical count, store replay or updates |
| [Inventory Position Calculator](../tools/inventory-position-calculator/README.md) | Current snapshot plus eligible inbound minus reserved demand | No authentic eligibility or live inventory |
| [Replenishment Proposal Planner](../tools/replenishment-proposal-planner/README.md) | Caller minimum/target/multiple/cap quantity arithmetic | No supplier selection or procurement authority |
| [Shipment Coverage Reconciler](../tools/shipment-coverage-reconciler/README.md) | Exact order/manifest/content/receipt quantity coverage | No delivery proof or shipment execution |

Each complete directory runs independently with Python 3.12/3.13 standard library.
Public MIT I/O/identity helpers have exact provenance pins; stock/fulfillment logic is
fresh. Complete identity accounting and exact snapshot pins prevent silent latest/best
selection and duplicated declared source/receipt slots. Invalid scopes withhold all
assessments. Logical negative, missing, stale, overdue, capped or shortfall findings
retain diagnostics without qualified scope pins. No quantities are silently clamped
into successful coverage; missing current quantities/proposals remain null where required.

Native tests require hardlink, linked-parent, changed-input, fresh-file and overwrite
fixtures. Actual connected CLI acceptance follows invented opening/movement declarations
through an explicitly adapted current stock snapshot, position, quantity proposal and
separate shipment receipt review. A public material-allocation adapter checks declared
reservations and an overreservation counterexample without duplicating its engine.
No original inventory, business documents, orders, accounts or operational actions are used.

Existing systems, packages, downloads, workshops, theme guide and root README remain
unchanged by this pass. The generated three starting workflows and prior announcement
index are preserved; a new announcement follows the index in the changelog. New tools
stay outside the frozen package plan; combined packaging remains deferred. Keep actual
inputs/reports private: these checks do not anonymize data, prove deliveries, establish
business completeness, verify policy correctness or authorize purchasing/stock changes.
