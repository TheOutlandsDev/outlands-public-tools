# Batch 65 - Independent ingestion-control tools

Four fresh generic MIT modules use explicit fictional contracts. Audit filename
candidates informed the scope; private original implementation files were not
consulted or selected. No customer/user records, private paths, credentials,
operational configuration, business mappings/formulas or assets are included.
Original files/filenames remain untouched; original-family clearance is incomplete.

| Independent tool | Scope | Evidence limit |
| --- | --- | --- |
| [Intake Mapping Diff](../tools/intake-mapping-diff/README.md) | Existing public mapping revisions, exact target/type/order/identity changes | No rename inference or compatibility guarantee |
| [Batch Replay Planner](../tools/batch-replay-planner/README.md) | Selected batch/history identities, pins and conservative manual-review/skip plan | No replay, reservation, complete-history or exactly-once guarantee |
| [Checkpoint Progression Checker](../tools/checkpoint-progression-checker/README.md) | Contiguous committed declaration coverage within a bounded ordinal window | Previous checkpoint/transaction truth unverified; no checkpoint write |
| [Ingestion Run Coverage Checker](../tools/ingestion-run-coverage-checker/README.md) | Exact expected/receipt cohort and declared source-row totals | No source recomputation or store-content verification |

Each full tool directory runs independently with Python 3.12/3.13 standard library.
Native file guards and the mapping validator are pinned existing public code.
Every batch/receipt row is accounted for; conflicting snapshots are never resolved
by selecting latest. Uncertain outcomes, gaps and aliases require review and
withhold plans/checkpoint suggestions/totals. Valid mapping changes remain visible
as descriptive codes. Reports still contain private IDs/counts/pins and must be
handled privately; structural PASS never authorizes execution or publication.

The dedicated Windows/Ubuntu matrix exercises known results, required native
fixtures, independent source copies and actual connected CLI workflows. The
interoperability fixture runs public intake and receipt reconciliation on invented
CSV and binds their actual pins/counts. Commit status remains explicitly asserted.
No database, service, original application or real records are used.

Combined packages/workbenches and release assets remain deferred until the rest
of the drive audit and the user's additional list are reconciled. Existing systems
and frozen Toolkit 0.6.0 downloads/package plans remain unchanged.
