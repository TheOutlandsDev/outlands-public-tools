# Target updates stay plan-only

The workbench reads only explicitly selected inbox packages and its registered private artifacts. It creates fresh private snapshot copies, metadata, plans, decisions, handoffs and index backups. It never downloads, installs or executes a payload/launcher, changes/removes target files, controls services/schedulers, probes endpoints, collects host/account inventory or discovers a live installation. The UI listens only on loopback. Test processes/browser dependencies operate qualification, not an update target.

Hash agreement proves byte agreement with the supplied pin. It does not prove authorship, trustworthiness, licensing, malware absence, authenticity of the review channel, working dependencies or safe application behavior. A candidate manifest pin covers the canonical supplied manifest; launcher/label metadata is covered by the candidate descriptor. A launcher pointing at a text file passes the structural declaration check while remaining untested as executable software.

Captured packages and baseline snapshots may contain arbitrary sensitive or untrusted bytes. They are retained privately and never run. The baseline is a selected saved package, not a measured current target or independently verified backup. All readiness/stopped/backup/removal/dependency facts are operator assertions. Plans retain blockers, checkpoints remain unperformed, and approval grants only a scoped private evidence handoff. Actual deployment, runtime acceptance and application-consistent recovery must be established separately.

Public first-party native Windows/POSIX I/O rejects links/reparse paths, hardlinks, nonregular inputs and changed identities during guarded reads. Package trees reject extra/missing files and directories, unsafe names and manifest mismatches. Captured output is new-only; originals are not modified. Input/output inventories are rechecked around capture, but this is not atomic live-tree capture or protection against hostile concurrent editing. Trusted quiescent parents and a trusted local operator/environment are required. Resource budgets are per operation/store; repeated output directories are not a global storage quota.

SQLite uses an exact schema, disabled extension loading, append-only triggers and typed hash-chain replay. Hashes are not signatures; an attacker who can coherently rewrite all local evidence/pins is outside this boundary. Session ownership uses an exclusive empty directory and process-local database lock. Stop the server before separate CLI use. Stopped recovery requires an independent operator assertion, clears only a checked empty stale directory and marks pending attempts interrupted. It never resumes, replays, repairs, deletes or adopts partial output. Never clear an active process's lock.

HTTP requests require the session token, accepted Host and same-origin POST boundaries. Responses use no-store, nosniff, no-referrer and CSP. Supplied content is displayed as text. There is no authenticated multiuser, remote/TLS, encrypted storage or OS sandbox mode. “Offline” describes this workbench's behavior, not isolation from other local processes or software.

Snapshots, source selectors, manifests, filenames/hashes, labels, dependency text, launcher arguments, actor/reason notes, histories, index backups and handoffs can expose private information. Generated reports are not automatically sanitized. Keep instances outside source control and separately review exact future shared files for content and rights. Approval never grants public-release permission. Source packaging covers only the pinned allowlist and excludes generated instances, logs, databases, reports, captured payloads and runtime binaries.

Production deployment, arbitrary archive extraction, real package installation/resolution, live target drift, service controls, executable acceptance, hardware/power-loss resilience, encryption/signatures, hostile filesystem races and complete instance restoration remain outside qualification.
