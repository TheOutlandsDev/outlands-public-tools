# Safety and privacy boundaries

This release contains fresh first-party code, unchanged public first-party native
I/O helpers and invented fixtures. Original templates, source programs, documents,
prices, customer data, logos, private paths, source mappings, credentials, generated
operational documents and third-party assets remain separate and excluded.

All future values, template labels/text, optional-section content, operator
assertions, journals, previews, builds, downloads, handoffs and backups are private.
Omitting a visible section does not erase corresponding input values from private
journal/history/handoff data. Fixed neutral properties do not anonymize document
body text. Review assertions are not factual, privacy, rights or identity proof.
Nothing here automatically authorizes sharing a generated file.

Templates cannot include expressions, code, remote resources, uploaded DOCX parts,
images, macros, embedded objects or arbitrary XML. The writer emits a small fixed
OOXML format with literal text and known relationships. Build verification pins
every byte and part against its retained semantic model. Future viewers may still
interpret literal text or apply their own settings; universal Office compatibility,
font coverage and document authenticity are not guaranteed.

The browser binds loopback, uses a per-process token, exact Host and allowed Origin
checks, bounded requests, no-store responses, no CORS and text-only DOM rendering.
Downloads require the token and a verified registered build ID; no arbitrary file
path can be requested. It is a trusted single-operator local UI, not a remotely
accessible authenticated multiuser service. Do not expose it or share its token.

Windows handle/reparse/link checks and POSIX no-follow/nonblocking/identity checks
reuse unchanged reviewed public helpers. Private instances are refused inside
source/Git; output creation is exclusive. Trusted parents and no hostile concurrent
filesystem editor are assumed. Checks do not defeat every pathname replacement
race or provide an OS sandbox. Windows ACL confidentiality is not independently
verified; use a private trusted parent directory.

Started jobs are durable before writes. Failure/interruption retains partial
output; only a final marker plus completed journal registration is accepted normally.
Explicit stopped recovery marks pending jobs interrupted without deletion, replay,
resume, overwrite or adoption. A lost successful response can leave a completed
record; inspect history before another deliberate action. A new build is a fresh
independent job, not an automatic retry.

Index backups contain private template/value requests and journal records but omit
artifact files. Preserve complete instances separately as needed. There is no
automatic restore, repair, rollback, cleanup or compaction. Finite caps do not
bound all accumulated disk use. Production, power-loss/hardware recovery,
long-term retention, encryption, signatures and hostile-database acceptance are
unverified. The interpreter, OS and document viewer may have additional side effects.
