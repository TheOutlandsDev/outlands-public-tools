# Plan-only and private-instance boundaries

The evaluator is a pure function of a strict profile and supplied observations. It never reads actual configuration/environment values, searches PATH, inspects processes/host/account/hardware, checks prerequisite file metadata, invokes target programs, resolves DNS, probes ports, connects services or installs/modifies anything. The browser server binds IPv4 loopback only. Python, SQLite and loopback HTTP operate the workbench itself; they do not execute setup targets.

Supplied `PRESENT` assertions, filenames, manual operator labels and reviews are unverified. Neither successful contracts nor a reviewed plan establish permissions, versions, reachability, operational safety or successful execution. Step text is literal, never an expression, template, include or shell command. The workbench has no execution adapter. All reviewed plans explicitly deny execution/publication permission.

The private instance must be outside the source checkout under trusted ordinary parents. Public first-party Windows/POSIX guarded I/O rejects links/reparse paths, multi-link files, unsafe path selectors, nonregular input and replacement outputs; native checks remain platform-specific. SQLite uses an exact schema, fixed version, disabled extension loading, append-only triggers and typed hash-chain replay. Hashes detect changes relative to retained pins; they are not signatures or protection against an attacker rewriting all private data coherently.

One trusted local operator/process owns an instance, using an empty exclusive session directory and process-local database lock. Stop the server before separate CLI use. Recovery requires an independent stopped-process assertion and only clears a checked empty stale directory and marks pending jobs interrupted. It cannot prove another process is stopped. An active process must never have its lock cleared. Per-file writes are exclusive; there is no multi-file atomicity or automatic replay, repair, adoption or partial-output deletion. Failures retain evidence and use fixed errors without native paths/details.

HTTP requests require the current session token, accepted Host and same-origin POST boundaries. Responses use no-store, nosniff, no-referrer and a restrictive CSP; supplied content uses text nodes. There is no authenticated multiuser boundary, TLS, remote server mode or encrypted storage. The UI token is for a trusted local session, not an authentication product. Untrusted local processes/users and hostile concurrent filesystem editors remain outside the supported threat model.

Configuration results omit setting values, unknown setting names and observed filenames. **Profiles, choices, step notes, IDs, hashes, actors/reasons, private history, index backups and handoffs can still disclose information.** In particular the journal retains full observations/settings. Keep them private. Review assertions do not anonymize content or grant rights; a separate exact-file/content/rights review is required before any future sharing. Source packaging accepts only the pinned source allowlist and excludes all runtime instances, reports, databases, logs and generated artifacts.

No production suitability, full installer, live drift detector, real dependency resolver, OS sandbox, authenticated audit, encryption/signature system, automatic recovery, power-loss/hardware resilience or complete instance restore is claimed. Store backups include requests but omit artifact files; preserve a stopped full instance separately if needed.
