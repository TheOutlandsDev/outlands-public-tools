# Validation and acceptance boundary

The release requires fictional CLI, real HTTP/Chromium and native file/store qualification on Windows and Ubuntu with CPython 3.12 and 3.13. Standard-library tests independently check nine expected results, three-step blocker propagation, strict integer/rule behavior, tuple-only connection conflicts, exact relative-name declarations, unknown/optional states, topological order/cycle refusal, value-free result output, revision and evaluation comparisons, review/hash/head refusal, immutable artifacts, schema/hash/typed-result tampering, partial output, actual owned-child termination and explicit stopped recovery, private handoffs and index contents.

Actual Chromium acceptance exercises complete save/evaluate/review/inspect/export/backup flows, changed revisions/results, missing/unknown/conflicting declarations, literal markup with no remote request, integer type failures, draft invalidation, stale requests, lost-response handling without automatic retries, partial writes, tamper rejection, historical pins, private history, explicit revision loading and narrow keyboard-accessible layout. Browser evidence uses invented inputs only and stays outside source.

Local core tests contain 56 methods. On this local filesystem seven native link fixtures cannot be created and the POSIX-only FIFO case is inapplicable: 48 pass, eight skips. CI sets `WORKBENCH_REQUIRE_LINKS=1`; each Windows/Ubuntu job must pass all seven native fixtures (including a real Windows junction/POSIX directory link), and may skip only the opposite-platform FIFO/stream case. Twenty real Chromium methods are an additional gate. Skips are not protection proof; CI must complete before release.

CI also checks browser JavaScript syntax, the complete demo, pinned source inventory, deterministic source ZIP, documentation and JSON syntax. Each platform's source ZIP digest must match the reviewed release archive. Clean extraction and copied README setup/package commands are checked outside the source checkout. The source/release audit reviews exact changed files, retains harmless inherited public-URL findings with pinned dispositions, and verifies remote inventory and anonymous downloads.

No real setup target, program, installation, filesystem layout, configuration environment, host inventory or network service is exercised. Test processes and Chromium are controlled qualification tools, not target execution. A separate engine test forbids subprocess/network/host-file calls during evaluation. Real machine readiness, operational security, production deployment, hostile concurrent editing, complete restoration and power-loss/hardware behavior remain unvalidated. All input/history/export privacy limits in [safety](SAFETY.md) apply.
