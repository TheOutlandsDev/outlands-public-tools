# Validation and acceptance boundaries

The 67-test standard-library suite covers strict dataset/experiment contracts, declared feature availability, delayed-label purging, as-of boundaries, group crossing, train-only preprocessing and model invariance, stable sigmoid, one-step gradient arithmetic, independent tied-score AUC/AP and loss/confusion/reliability oracles, complete fictional workflow, immutable/idempotent artifacts, optimistic review, approval-gated exports, model JSON replay, cohort comparisons, store rollback, append-only schema, backup, actual HTTP handlers and native Windows/POSIX file guards.

Ten real Chromium tests exercise dataset import, configuration forms/JSON, actual training, separate evaluation, model/threshold/reliability rendering, immutable conflicts, timing/pin rejection with retained drafts, review reset and export gates, stale-note retention, comparisons, backup, literal untrusted-title rendering and a 390-pixel keyboard workflow. Fresh private instances use generated records; external requests are refused. Automated interaction is not manual usability or complete accessibility conformance.

Local tests record unavailable native link creation as four skips, plus one opposite-platform fixture. CI requires all applicable native links and both suites on Windows/Ubuntu CPython 3.12/3.13. A skipped native fixture is not a passed check. Browser packages and paired Chromium are separately installed in the test environment; no binaries enter source packaging. JavaScript syntax and Markdown/JSON references are checked separately.

The full fictional demo has 240 rows, 118 train, 48 validation, 48 test and 26 exclusions. It prepares two experiments, stores evaluations separately, reviews/exports one, compares the same test cohort and validates a database backup. Test AUC is approximately .883478 and Brier .167048 for this generated task. Minor floating-point platform differences are allowed within a declared numerical tolerance; selected source ZIP bytes must match exactly.

The clean ZIP walkthrough verifies every selected source byte and deterministic archive metadata, repeats the workflow outside the checkout, independently recomputes metrics from exported predictions, verifies train-only means/scales and partition timing, replays numeric model predictions, and checks every report length/hash. Source-package checks do not substitute for runtime/browser evidence.

Actual child-process termination/restart stops an idle server, requires explicit stopped-session recovery and preserves stored preparation. It does not simulate death during file/SQLite commit. Native link rejection does not establish adversarial race safety. Excluded acceptance includes hostile SQLite/local storage, multiuser/remote deployment, mid-commit crash/power-loss durability, complete backup restore, representative datasets, independently verified feature provenance/group identity, model convergence/calibration, real customer data, production accuracy and medical/regulated use. Repeatedly viewing the holdout can invalidate it despite immutable records; no holdout secrecy is claimed.
