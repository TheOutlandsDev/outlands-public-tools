# Design and implementation boundaries

The application separates caller text, editor drafts, immutable project revisions, validation artifacts, local review and private source exports. Saving text never executes it; validation does not silently save a draft. A compare-and-swap expected project hash prevents a stale editor replacing newer work. Deletion is a revision, and historical source remains inspectable/forkable. Exact project and artifact pins distinguish an approved older export from a newer unreviewed edit.

The original owner-authored `validate_content` dispatcher supplies the starting extension/Python-AST method. The Python branch continues to parse supplied content. Strict public JSON decoding, bounded XML syntax/DTD refusal and unchanged public SQL preflight strengthen the other branches. The original JavaScript subprocess/runtime discovery, raw error details and local operational run-history writer are excluded. Fresh storage records only explicitly supplied text and neutral review metadata. See [origins](ORIGINS.md).

Python [AST parsing](https://docs.python.org/3/library/ast.html#ast.parse) checks syntax without importing the project. Parsing is not compilation, dependency resolution or runtime proof; a syntactically accepted program can still fail during compilation/execution. The separate child limits the parent wait and isolates ordinary parser failure, but is not an OS security sandbox. Python and SQLite are trusted local runtimes. Input/node/element/depth limits and owned-worker cancellation reduce work; they do not promise a total process-memory ceiling or protect against a hostile local user/runtime.

Public native I/O helpers reject applicable Windows reparse/hard-link/stream and POSIX linked/special-file inputs/parents. New outputs use exclusive creation; source checkout and its protected repository cannot become a private instance/export target. SQLite uses exact expected schema/version, bounded private state and append-only domain triggers. These are local guardrails, not hostile-database import or arbitrary filesystem-race guarantees. An empty session marker requires a stopped-process assertion after interruption. Database backups contain all stored project revisions/artifacts/reviews, but not inbox or exported files; no complete restore is claimed.

The browser serves loopback only with Host checks, random session token on API reads/writes, Origin checks for writes, bounded bodies, no-store responses, no-referrer and restrictive object/frame policies. Source/diffs/results use textContent or textareas, never caller HTML. It needs a trusted single local operator and browser; there are no remote accounts, authenticated reviewer identities or multiuser semantics. Tokens/runtime URLs and future data remain private.

Editor-mutating requests temporarily lock controls so delayed responses cannot overwrite a later draft. Validation captures an immutable revision; editor text can change during the check and remains a separate unsaved draft afterward. Selecting/completing a validation replaces its review form. Review conflicts retain the typed note, but selecting another artifact does not preserve unsaved notes automatically. Browser reload/closure can lose drafts; the unload prompt is best effort.

All source hashes are compared exactly. Diff previews are deliberately bounded, so a late change may appear only through differing full-file hashes and `preview_complete:false`. Source exports use fixed regular ZIP entries, full UTF-8 file text, explicit member pins and a final receipt; source/notes are not anonymized. Local approval is an assertion that must be followed by an independent exact-file content/rights review before any public release.
