# Fictional validation and acceptance limits

The standard-library suite has 55 methods covering exact contracts, portable paths/case collisions, byte/count limits, parser refusal/nonexecution, immutable edits/deletions/forks, stale hashes, diff coverage, distinct check identities, review gates/conflicts/revocation, historical export pins, complete ZIP metadata/member hashes, schema/append-only/state rollback, backup, HTTP guards and native I/O. Worker tests start actual owned children, including explicit cancellation/reaping, orderly active shutdown and parent timeout of a deliberately stalled child. Idle server termination/recovery is separate.

Fifteen actual Chromium workflows exercise import, browsing/editing/saving, add/delete confirmation, comparisons, saved/historical source, forks, backup, syntax/DTD/duplicate-key failures, review/export gating, fresh review state, stale editor/review conflicts, retained drafts/notes, literal untrusted text, real owned-worker cancel, historical validation refusal, atomic project/history selection after a failed request and narrow keyboard editing. Browser routes refuse outside requests; all inputs are invented and private stores start fresh. Automation is not a claim of manual usability or full accessibility compliance.

Local native-link creation can be unavailable on the selected drive: four skipped link fixtures and one opposite-platform case are recorded explicitly. Windows/Ubuntu Python 3.12/3.13 CI requires all four applicable native link fixtures rather than accepting that local limitation. Each matrix job must run both core and browser suites, the full fictional demo, source pins, deterministic ZIP and collection documentation checks. A skipped fixture is not a pass.

The demo returns five files, two project versions, four passed checks plus one explicitly unchecked file, one changed source file, two distinct validation artifacts, a pending second review, nine private export members pinned to revision 1 and a schema-checked backup. Independent clean ZIP replay checks every application source byte, all exported source bytes/member hashes, revision parent/pins, unchanged original fixtures, declared check outcomes and a fresh file-based CLI sequence.

Excluded acceptance: runtime/test/type/lint/dependency correctness of caller projects; complete XML/RDL or SQL validation; JavaScript/HTML/CSS checking or rendering; universal secret detection/anonymization; authenticated reviews; hostile stores/runtime/local processes or arbitrary races; OS isolation/total memory quotas; remote/multiuser hosting; shared/network-storage guarantees; hard-parent-kill cleanup, power-loss/mid-commit durability or complete-instance restore. Static/fictional runtime evidence never clears unrelated original data/source. Future projects, results, notes, exports and backups stay private.
