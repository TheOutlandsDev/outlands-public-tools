# Validation and interpretation limits

The timeseries-integrity-checks workflow qualifies Python 3.12/3.13 on Windows and
Ubuntu with source pins, known fictional contracts and mandatory applicable native
file fixtures. Hardlink and parent symlink/junction cases must run in CI; only
the opposite-platform boundary method per tool may skip. Local volume link skips
do not count as native qualification.

Known results cover grid gaps/duplicates/off-grid/unknown-series accounting, capped
and expanding multi-horizon folds, cadence/stride/gap boundaries and no partial
tail folds, exact observation pins/decimal normalization/caller-context independence,
strict revision availability ordering, inclusive cutoffs, delayed/missing actuals,
source aliases and conflicts, stale/future/incorrect feature references, exact
window coverage and global budget refusals. Invalid cohorts withhold derived plans,
resolutions or lineage; valid grid quality findings retain diagnostic coverage.

The actual CLI walkthrough copies each directory independently, verifies source
pins, runs fictional examples, checks new reports and overwrite/source-tree refusals,
fixed errors, raw input pins/no mutation and value omission. A connected four-tool
cohort validates a six-point invented grid, plans four one-step folds, resolves
each training prefix at its origin and verifies two-point contributor windows.
The existing public last-value baseline consumes those actual resolved prefixes:
predictions 4,2,4,2 at targets 2..5 have fictional MAE 2. This tests interoperability
and arithmetic, not useful real-data accuracy or an independent final holdout.

No actual calendar/time zone, clock, authenticated publication time, full version
history, original feature/model implementation, label availability, deployment,
service or real records are qualified. Declared timing can be false; as-of checks
cannot detect unseen future leakage or prove the running feature code used these
contributors. Repeated/overlapping backtest targets are not independent samples.
No model training, feature calculation, production evaluation or target changes.
Real inputs/reports remain private. Native guards require trusted quiescent storage;
they do not sandbox hostile concurrency or impose OS resource quotas.
