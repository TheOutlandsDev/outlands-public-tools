# Validation

Run `python -B source_check.py` and `python -B -W error -m unittest discover -s tests -v`
from this independent directory with Python 3.12/3.13. Collection acceptance runs
`python -B -W error -m unittest discover -s tests -p test_quote_pricing_tools.py -v`.
The dedicated workflow requires Windows/Ubuntu Python 3.12/3.13, native link fixtures
and actual standalone/connected CLI execution. Only the opposite platform's method
may skip; missing applicable native evidence fails. These commands define validation;
the publication receipt records actual executions separately from this source contract.

Known answers cover all-units tier boundaries, exact decimals, half-up/even/down ties,
per-line rounding, ordered fixed/rate adjustments, over-discounts, complete claim
coverage, stale whole-record references, subminor price changes, scenario comparability
and selected-scope limits. Adversarial cases include malformed data, conflicting IDs,
normalization, raw limits, bool/int distinctions, precision, unknown fields and fixed
diagnostics. Native fixtures cover actual read/write/hash, overwrite, changed inputs,
hardlinks, linked parents and platform-specific ambiguity. No mock substitutes for
required native evidence. Every complete directory includes its own pinned MIT helpers.

Collection tests copy complete independent directories, verify source manifests and
run each CLI without siblings. Fresh output readback, overwrite/source-output refusal,
unchanged input bytes, game/AI examples and a connected HVAC book -> lines -> totals
projection are exercised. The fourth tool compares the same HVAC basket under two
books. No original implementations or operational data are consulted. This provides
supplied-declaration/arithmetic evidence, not live transactions, commercial policy,
browser, customer approval, tax, privacy or rights verification.
