# Validation and interpretation limits

api-exchange-checks qualifies Python 3.12/3.13 on Windows and Ubuntu. Mandatory native
fixtures cover read/hash, fresh write/readback, hardlink-input refusal, linked-parent
refusal, changed-input detection and overwrite refusal. Only opposite-platform methods
may skip; local volume skips are not native proof.

Known-answer/adversarial tests cover exact method/route and field/variant contracts,
conservative overlap detection, renamed parameters, alias status/field slots, nested
duplicate rejection, custom headers, HEAD/bodyless status limits, choice normalization,
strict typed rules and operation caps; request method/path/media/body checks, missing
and unknown fields, no boolean/integer/string coercion, range/choice violations,
expected-negative behavior, header controls and unsupported decoded representations;
exact response references, error variants for invalid requests, missing/alias response
coverage, unknown statuses, raw-value suppression, expectation separation and assessment
budgets; exact comparison assumptions, version-specific pin rebinding, invalid expected
cases, missing/added/changed cohorts and operation identity conflicts. Top-level identity
cohorts test complete duplicate/conflict/rejected accounting. Public strict JSON/I/O
tests preserve source, no-overwrite and fixed-error protections.

Actual standalone acceptance copies each complete tool, verifies source pins, runs
CLIs, creates fresh reports, refuses overwrite/source output, checks raw-input hashes,
unchanged inputs/fixed errors and absence of action artifacts. Connected invented HVAC
service-proposal records bind exact operation/request/response cohorts through four
CLIs. Game-build operations and AI/software evaluation requests contain no assets/models,
endpoints, credentials or real traffic. An explicit collection-only adapter supplies
fictional scalar body values to the existing public Configuration Contract Checker,
including out-of-range refusal. Its engine is not duplicated or imported. A separate
actual CLI example distinguishes an invalid request from its valid declared error response.

These custom declaration tests do not establish full HTTP/OpenAPI/JSON Schema support,
wire encoding/decoding, real responses, live API compatibility, authentication, security,
privacy, rights or readiness. Original private code, schemas, routes, real payloads,
records, customers/users, paths, credentials, endpoints and deployment details were not
consulted or selected. No HTTP clients, servers, endpoint probes or target changes run.
