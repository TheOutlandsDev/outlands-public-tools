# Standalone qualification contract

Qualification selects ordinary CPython 3.12, 3.13, 3.14 and 3.15.2 on Windows x64 and Ubuntu x86_64. Actual interpreter patches, source and archive hashes, selected test IDs, named skips and outcomes belong to release VALIDATION.json. A future run or a skip is not counted as a passing assertion.

The 94 original methods comprise 39 selected transfer regressions from the shared transfer/maintenance source and 55 additional I/O tests. Preservation checks retain 130 assertion calls (125 in tests and five in helpers), sixteen supporting helpers, exact selected shared-node bytes and the raw 55-test file. Thirty copied-runtime CLI methods run fresh processes against only `transfer.py` and `transfer_windows.py` in external temporary workspaces. Each lane selects 124 methods, or 992 executions across eight lanes. Qualification rejects missing methods, failures, unexpected skips and invalid capability claims.

The ten POSIX tests on Windows and eighteen Windows tests on POSIX remain exact named platform skips. Applicable native links, hardlinks, junctions and descriptors are required in hosted qualification. Any permitted short-name absence must be observed successfully on the same path. Local-only Windows privilege error 1314 can explain five specific symlink skips, but cannot replace hosted native execution. Hardlink/junction failure cannot be skipped. See VALIDATION.json for actual per-lane outcomes.

The formats remain `reviewed-source-package-v1` and `opaque-data-handoff-v1`. The only runtime change is header boundary selection for flat downloads: a literal collection layout protects the collection, and a standalone location protects its runtime folder. Functions/classes and native I/O behavior are preserved. The historical [I/O guide](../IO-SAFETY.md) describes its earlier collection-layout qualification; its opening layout requirement and historical counts are not this release's standalone contract.

Copied-runtime checks cover externally pinned source packages, opaque backup/verify/restore, optional verify pins, mandatory restore pins, stopped assertions, no overwrite, source-output boundaries, malformed metadata, changed inputs, links, short writes, read-back checks and retained failed output. Handled CLI refusals use fixed error JSON and exit 2; handled Windows interruption uses exit 130. POSIX/library interruption propagates. Help and success output are not universal redaction APIs.

The source gate checks a finite text/source inventory and SHA-256 manifest. Deterministic ZIP construction fixes member order, timestamps, file attributes and compression; members must match committed source. Independent builds must reproduce ZIP and build-manifest bytes. Fresh qualification uses external workspaces, new no-pip environments and zero distributions, with runtime/fixture affinity and preserved source bytes. Interpreters, environments, private evidence, real records and raw logs are excluded from the ZIP.

The thirteen-case [usage exercise](../USAGE.md) checks five complete successful JSON results and eight complete fixed refusals. It preserves five fictional input files and both runtime files. It verifies exact output trees, a deliberately tampered copy, existing-destination preservation and absence of application bytecode or undisclosed files. Synthetic stopped-state bytes do not establish consistency for an actual application or database.

Use trusted quiescent local files and one operator. Sampled native checks do not create atomic snapshots, hostile-filesystem isolation, hard I/O deadlines, ACL confidentiality or preservation of application state. No real application backup, service lifecycle, network/cloud storage or operational deployment is qualified. Opaque payloads remain private and unencrypted; selected files are never imported or executed.
