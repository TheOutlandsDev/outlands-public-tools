# Qualification contract and limits

Four native profiles use Windows x64/Ubuntu x86-64 with hash-pinned Python 3.12.16
and 3.15.2. Each must independently reproduce exact source ZIP/build-manifest bytes,
extract fresh source, install locked binary wheels into a new venv, check all exact
versions/pip consistency and pass all 24 selected methods with zero skips, failures,
errors or warnings. Workflow configuration alone is not evidence; release
VALIDATION.json records actual tested commits, SDKs, jobs and results.

The checks cover retained implementation/engine pins, all nine original assertions
with fictional public fixtures, the legacy CLI under UTF-8 and byte parity with the
guarded result, signed VX/VY measurement oracles, medians/differences, exact reference
preference and counted corner fallback, missing references, aliases/conflicts,
manifest/XML/PNG limits, declarations/duplicates/nonfinite/status/depth refusal,
missing/escaped paths, failed analysis, output exclusivity, input immutability/change
detection, pinned-source tampering and copied CLI behavior outside source folders.
Reparse refusal is always tested; native symlinks are additionally exercised when
host privileges permit creation. This is not a promise of Windows link privileges.

The first private Windows run executed 23 methods, with one legacy completion-print
failure under cp1252 after CSV writing. The original source was not changed. UTF-8
legacy invocation passed all 23; the subsequent added budget method brings the
release suite to 24. The failure record remains private rather than being erased.

Only invented images/rows/XML are used. This app does not detect objects or execute
YOLO. It uses fixed sampling and bypasses the engine's expanded Rev 3b QC gate;
that retained distinction is tested. Featureless-input refusal is a separate launcher
policy. Sigma aggregation, assumed pitch and pixel bias are not calibrated accuracy
or uncertainty. Real instruments/specimens, interactive Tk use and production
metrology remain unverified. Stable trusted directories are required; the checks do
not contain hostile concurrent filesystem changes. Original legacy discovery,
dynamic analyzer loading, partial failures and overwrite behavior remain available
only through the unchanged legacy command, outside the guarded launcher's promises.
