# Security and privacy

For an exploitable issue, use the repository's private vulnerability reporting
option if it is available. Otherwise open a minimal public issue asking for a
private reporting channel without including exploit details, customer records,
credentials or private paths. There is no guaranteed response time.

This release has no encryption, authentication, permission roles or remote
server. Store files/reports/backups are private application data; use trusted
local storage and operating-system permissions. Do not send real data to public
issues. Avoid arbitrary databases received from others. Schema/header checks and
hashes do not establish origin or stop an owner altering local records. Limits,
path checks and CSV/HTML escaping are defensive checks, not a universal sandbox.
