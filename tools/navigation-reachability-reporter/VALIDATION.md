# Validation

Run `python -B source_check.py` and
`python -B -W error -m unittest discover -s tests -v` from this complete directory.
Collection acceptance runs
`python -B -W error -m unittest discover -s tests -p test_navigation_tools.py -v`.
The dedicated workflow requires native Windows/Ubuntu Python 3.12/3.13. Set
OUTLANDS_INTAKE_REQUIRE_LINKS=1 so missing applicable link fixtures fail. Only the
opposite platform's test method may skip. The private publication receipt records
actual runs separately from these source validation instructions.

Known answers and adversarial cases cover canonical paths, exact revisions, whole-manifest
pins, nested identity ambiguity, alias termination/cycles, terminal fragment resolution,
missing targets, whole-link cohort pins, starts, reachability, duplicate edges, strongly
connected navigation groups, dead ends and observation-scoped comparisons. Equal invalid
targets never become clean comparisons. No mocks replace required native fixtures.
Read/write/hash, hardlinks, linked parents, changed inputs, overwrite/source-output refusal
and platform ambiguity are exercised using disposable fictional native files.

Actual complete-directory copies verify source manifests and run standalone CLIs without
sibling imports. Fresh reports and immutable input bytes are checked. A four-tool fictional
HVAC guide handoff checks exact shared pins, target resolution, reachable pages and scenario
equality. Video-game and AI/software examples are wholly invented. Connected negative cases
retain broken-target graphs and stale handoffs as findings. No original private source or
operating instance is opened. This proves only the supported supplied-declaration behavior.

The existing frozen collection's browser/render checks remain separate evidence for its
existing applications. They do not establish browser or DOM behavior for these new tools.
