# Standalone qualification contract

The target matrix is ordinary CPython 3.12, 3.13, 3.14 and 3.15.2 on Windows x64 and Ubuntu x86_64, with separate pinned Git 2.56.1 executables. Windows uses official MinGit 2.56.1.windows.1; Ubuntu builds the official Git 2.56.1 source with the selected limited local feature set. Archive/source pins, actual executable hashes, interpreter versions, source/ZIP hashes, test IDs, named skips and outcomes belong to release VALIDATION.json. A pin recipe is not a bundled binary, system installation or cross-build binary reproducibility claim.

All 54 original methods remain in the raw original suite: 37 Reporter and seventeen Porcelain methods, retaining 64 assertion calls (sixty in tests and four in five helpers). The runtime, example generator and original fixtures are preserved. Thirty additional copied-runtime methods run fresh Python processes against copied source and explicit pinned Git. Each lane selects 84 methods, or 672 executions across eight lanes. Missing methods, failures, unsupported skips or invalid capability claims stop qualification.

Applicable native link/junction and alias-containment checks are required in hosted qualification. Opposite-platform cases remain exact named skips. Actual Windows error 1314 can explain a permitted local-only symlink skip; strict hosted lanes must exercise the native case. Successful same-path short-name absence is distinct from native alias acceptance; no universal 8.3 alias creation is claimed. Git is required and its absence cannot skip the suite.

The copied-runtime suite covers ordinary/linked worktrees, unborn/detached heads, local-ref comparisons, staged/unstaged/untracked/unmerged status, malformed porcelain/config/layout refusals, isolated Git environment and helpers, unchanged source/index/control bytes, new-only outputs, independent manifest readback, native paths and owned-child failure bounds. Fixture creation can commit only in newly generated disposable repositories. No existing project or remote service is used for acceptance.

The raw parser is preserved. An untracked nested repository can yield a directory-shaped `? nested/` record, which the portable path subset refuses with exit 2 and `INCOMPLETE` / `STATUS_PATH_UNSUPPORTED` before creating output. Qualification checks that refusal and input preservation; it does not claim a successful partial inventory of nested repositories or universal Git-layout support. The earlier README's loose directory-entry description is corrected in current documentation, while historical format/validation bytes remain intact.

The [eleven-case guide](../USAGE.md) runs the preserved generator, five successful report scenarios and five expected refusals. It compares complete stdout/stderr bytes and statuses, independently reads every report/manifest, checks unchanged fixture/runtime bytes across inspector calls and retains the generated fictional work for private inspection. Commit object IDs can vary; the guide validates their actual shape/readback and does not publish a fabricated fixed ID.

The source gate checks a finite text/source inventory and member hashes. Deterministic source ZIP construction fixes ordering, timestamps, regular-file attributes and compression; members must match committed reviewed source. Independent builds must reproduce the ZIP and build-manifest bytes. Fresh extraction/no-pip environments must have zero installed distributions, exact runtime/fixture affinity and unchanged original source bytes. Git/Python binaries, compiler output, environments, real repositories, reports and raw private evidence are excluded.

The historical [format contract](FORMAT.md) and [earlier validation record](VALIDATION.md) retain original Python 3.12–3.14 wording and earlier outcomes. Their supported-format, trust and output limits remain applicable; current matrix acceptance comes from this contract and release VALIDATION.json.

The inspector issues no fetch, push, stage, commit, checkout, reset or cleanup command. Git can read tracked file bodies internally to calculate status. Global/system isolation can change observations relative to interactive Git, and stored-ref comparisons are not remote freshness. A successful report is not a backup, content inventory, secret scan, license/ownership verdict or recovery proof. Sampled metadata and bounded owned children are not atomic snapshots, hostile-process/filesystem isolation or hard native startup/I/O deadlines. Real migration recovery, hostile mutation and network/cloud storage are outside acceptance.
