# Private reconciliation workspace

Select stable, regular before/after record-set JSON and a caller-authored contract in a private directory outside source. Default reports retain identities, exact totals, changed field names, row positions and fingerprints. Full before/after records are opt-in. Omission does not anonymize data. Contract suitability, real-world completeness, units and business meaning remain caller assertions.

Any rejected row or conflicting identity group withholds the entire comparison and totals, even when other rows are accepted. A qualified match establishes only the supplied-set relationship. No source adapter, SQL query, currency/unit conversion, record import or external-system write is performed. The CLI uses the selected interpreter's ordinary default Decimal context; callers altering a library context must assess that distinct scope.

Keep all three inputs and their ancestors trusted and quiescent. Same-file input roles are allowed when the selected file is an ordinary single-link file. Linked and multilink routes are refused. Choose a fresh external report name. The reviewed Windows create-new/reparse-point correction refuses existing leaves, including dangling entries. Failed writes can retain unconfirmed partial output; preserve it and choose another name. Windows ACLs inherit from the selected parent. Cooperative resource limits and sampled filesystem checks are not an operating-system sandbox, atomic snapshot or hostile-writer guarantee.

No actual records, operational contract, generated report, SDK, account, credential or private evidence is bundled. Obtain CPython separately; runtime imports use only its standard library. Shared toolkit XML boundary tests do not add XML input support to the JSON reconciliation CLI.
