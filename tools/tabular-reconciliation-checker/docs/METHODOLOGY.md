# Reproducing bounded reconciliation evidence

Use fictional before, after and contract JSON inputs in an owned private workspace, with source kept separately. Define record schema, exact identity fields and numeric total fields explicitly. Do not infer unit conversion, tolerances, business rules or source completeness. Preserve the three source byte hashes separately; a comparison result is a statement about those supplied buffers.

Author complete expected reports as data: explicit row accounting, change identities/classifications, changed-field order, old/new normalized record hashes, unchanged count, exact total/delta strings and side/position/code issues. Do not use the comparator, its scalar conversion or grouping routines as an expected-results oracle. Standard JSON serialization and manually stated arithmetic values are separate from matching logic.

Always include the equal-19-total example: changed, missing and added records remain visible despite delta zero. Verify identical/reordered sets, normalized identical duplicates, empty sets and one-sided records. Totals count unique qualified records once, rather than counting duplicate rows twice. Counts conserve every input row. The tool does not return an accepted-record list or duplicate source-row provenance list.

Verify global qualification before interpreting comparison payloads. Any rejected or conflicting row on either side makes changes, unchanged_records and totals null, including with `--show-values`. Test this while independent valid records remain. Separate this review result from a fully qualified empty match. Diagnostic positions and fixed codes omit rejected/conflicting payload values.

Check strict integer/boolean/date/text/decimal types, explicit null, missing/extra fields, contract identity/total suitability and duplicate JSON keys. Text's control predicate is ASCII C0 plus DEL, not a universal Unicode-control filter. Default qualified changes disclose identity values, changed field names and hashes; selected totals and raw input hashes also remain visible. Only full changed records are opt-in. Neither mode anonymizes inputs.

Use the selected coherent SDK and fresh no-pip runtime, with C Decimal affinity and measured default precision/rounding/context verified. Bounded declared-limit sums/deltas fit this environment. Library calls with changed ambient Decimal context require their own validation. Shared-toolkit XML boundary evidence does not establish XML product ingestion. No generator, Office/SQL/provider connector or external-system write is exercised.

Invoke actual script entrypoints and snapshot all three input roles and every pre-existing workspace artifact before each operation. Check independent per-input byte bounds, hardlinks, native path protections, same-file before/after use, new-output exclusivity and source-output refusal. A controlled backend write interruption retains and hashes five unconfirmed bytes, then proves that name cannot be silently reused. This is synthetic I/O evidence, not rollback, power-loss durability, full metadata preservation or an atomic filesystem snapshot.

Inventory every fixture, contract, report, observation ledger and SHA-256 manifest. Bind working/committed guide source identities separately and retain unsuccessful attempts under their actual identities. Public release gates compare selected Git blobs, exact source ZIP members, actual CI receipts, byte checksums and anonymous asset readback. Generic methods and invented examples are public; real records, private paths, logs and evidence remain local. No independent writer or production interoperability claim follows from fictional checks.
