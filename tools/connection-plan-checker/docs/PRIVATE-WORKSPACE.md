# Private workspace

Extract public source into a fresh directory. Choose a separate existing,
user-owned private parent for Python/venvs, fictional work, actual declarations,
stdout captures and qualification receipts:

```text
source/connection-plan-checker-0.1.0/  selected source only
private/connection-plan/
  venv312/                             separate no-pip environment
  fictional_walkthrough.py             private copy of the usage driver
  fictional-demo/                      new owned binding metadata only
  actual-plan.json                     real declaration, private
  captures/                            caller-selected stdout/diagnostics
  qualification/                       extraction, environments and receipts
```

Select the intended interpreter and `connection_check.py` explicitly. Provide
`--plan FILE`; no default/environment plan, output writer, installer, launcher,
firewall rule, socket/DNS probe or process inspection exists. The checker reads
only the selected JSON and prints stdout. Caller redirection/capture code is
separate and may overwrite output; choose new private capture paths deliberately.

The schema accepts 1–128 bindings with a unique neutral ID, exact `tcp`/`udp`,
exact `127.0.0.1`/`::1` and integer port 1–65535. It has no hostname, wildcard,
remote endpoint, range, command, identity, process or installation fields. Do
not strip real vendor configurations or substitute aliases to force them into
this declaration-only convention.

Every member of an exactly repeated transport/address/port tuple conflicts,
including UDP. TCP/UDP and the two address spellings stay separate. Checks
retain input order; groups follow first tuple appearance and members declaration
order. These are declaration relationships, not runtime bind/reuse/exclusivity
or dual-stack rules. A distinct declaration can still fail in a real application.

Results omit binding transport/address/port fields, selected paths and native
details but retain IDs, counts, evidence and conflict-group relationships.
Those fields can disclose a design. Fixed errors do not anonymize caller logs,
captures or formatted tracebacks. Keep actual controls/results private and
review a separate export before sharing.

Use fully spelled canonical trusted paths and stable ordinary files. Path
components are checked after absolute-path normalization; there is no earlier
original-spelling suffix check. Actual fictional Windows probes on Python
3.12.7/3.15.2 accepted canonical, leaf-dot, leaf-space and parent-dot forms with
exit 0; parent-space returned exit 2/`INPUT_PATH_INVALID`. These preserve
input/runtime bytes but establish no blanket original-suffix refusal. Input requires supported ordinary
single-link/type/ancestor identities. Observed links/reparse/special/multi-link
inputs and sampled changes are refused. These checks do not retain an atomic
snapshot, deny all writers or establish a hostile-filesystem boundary.
Arbitrary mount/drive aliases, rebinding, remote/cloud/virtual/live storage,
blocked I/O, power loss and ACL privacy remain outside acceptance. OS reads
can involve network storage without a socket/DNS probe. Access metadata and
Python caches are separate.

Input is at most 64 KiB with bounded binding/token/port values. These are not
total CPU/memory/JSON-depth/deadline or storage quotas. Require complete JSON
and actual exit/status; interruption or stdout failure can leave partial
captures. There is no checker-owned output tree to roll back. Fictional work
is retained for inspection without automatic cleanup. Requested modes depend
on OS/Python/ACL behavior and are not a confidentiality guarantee.

User-owned Python/venvs do not inherently need administrator access. Respect
device policy/OS prerequisites without bypasses. No pip distribution, network,
model or account is needed; interpreters remain separately licensed. Build/
qualification outputs must be new private paths outside source with existing
parents. Publish reviewed source and sanitized actual validation only, excluding
operational plans/results, IDs/relationships, personal paths, credentials,
private source, interpreter/dependency binaries and raw logs.
