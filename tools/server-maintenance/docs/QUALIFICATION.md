# Standalone qualification contract

This qualification targets ordinary CPython 3.12, 3.13, 3.14 and 3.15.2 on Windows x64 and Ubuntu x86_64. Actual patches, test IDs, named skips, source/ZIP hashes and results belong to release `VALIDATION.json`. The required gates below do not count a skip or a future run as a pass.

The runtime pair and all 61 original methods are preserved against reviewed collection source: fifteen maintenance regressions selected from the shared transfer/maintenance suite and 46 input tests. The standalone adapter selects only maintenance fixtures; it does not ship unrelated transfer runtimes or tests. The selected source retains 86 assertion calls (83 in test methods and three in nine direct helpers). Method/helper/assertion preservation and runtime/fixture import affinity are checked. Native capability enforcement surrounds the preserved bodies rather than replacing their assertions or application checks. See [provenance](PROVENANCE.md).

Thirty `test_download.Download` methods copy only `maintenance.py` and `maintenance_windows.py` into owned private directories and run the current interpreter in fresh processes. They cover calendar/lifecycle/readiness results, valid deferred statuses, fixed argument/input errors, byte/JSON/field limits, input preservation, supported hard links, native paths and interruption behavior. Inputs are invented declarations. Every result remains nonexecuting; no actual service, process, network probe or schedule is accepted by qualification.

Each lane selects 61 original plus 30 copied-runtime methods: 91 per lane and 728 across eight lanes. Applicable native link/junction/descriptor cases are required in hosted qualification. Exact opposite-platform tests remain named skips; alternate short-name absence must be a successfully observed capability limit. Local Windows symlink error 1314 is separately documented and cannot substitute for hosted native execution. Failures, missing methods, unexpected skips and invalid skip claims stop qualification.

The source gate verifies an explicit finite text/source inventory and SHA-256 manifest. The source ZIP uses fixed ordering, timestamps, regular-file attributes and compression settings. Each member must agree with committed reviewed source. Independent builds must reproduce both ZIP and build-manifest bytes. Optimization is refused by validation helpers that require assertions.

`packaging/qualify.py` uses `--packages`, `--workspace`, `--report` and optional `--reference-build`. It uses new external workspace/report paths, verifies/extracts the selected archive, creates a fresh `--without-pip` venv and checks that it contains no distributions. Imports and subprocesses must use the extracted runtime and selected interpreter. Runtime and original fixture bytes must remain unchanged; source bytecode and undisclosed application files are refused. Dependencies, interpreters, environments, operational records and raw logs are excluded from the source ZIP.

The planner accepts existing stable hard-linked regular inputs. No blanket hardlink refusal is added. Windows input spelling/native-handle checks are stricter than POSIX behavior. Windows handled interruption has exit 130 and fixed `PLAN_INTERRUPTED` JSON; the POSIX CLI/library retain propagation. Valid plans with review/defer statuses and incomplete readiness declarations still use exit 0. There is no report writer, overwrite mode, source-output boundary, version command or maintenance execution feature.

The seven-case [usage exercise](../USAGE.md) compares complete outputs and retains five fictional input files unchanged. Its wrapper creates the inputs; the planner only reads selected inputs and writes stdout. `execution_performed` stays false. Observations are supplied assertions, not independently verified conditions.

Use one operator and trusted quiescent local files. Sampled metadata checks do not create an atomic snapshot, hostile-filesystem isolation, hard I/O timeout or ACL confidentiality proof. Mapped/network/cloud storage, permission policy, arbitrary mounts and hostile mutation are outside acceptance. No actual backup/restore, machine restart, target readiness, operational record or deployed workflow is validated. Keep real input, observations, diagnostics and saved outputs private.
