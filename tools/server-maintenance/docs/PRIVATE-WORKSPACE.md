# Choose a private local workspace

Use an existing trusted user-owned local parent outside source and any public or synchronized checkout. The `D:\Private` and `D:\Source` usage examples are fictional placeholders. Choose canonical fully spelled drive paths on Windows and absolute local paths on Ubuntu.

Create new child paths for an optional no-pip environment and the walkthrough script. Call the environment's Python directly; activation, an execution-policy change and global installation are not required. Actual file/executable permissions, application controls and workplace policy still apply. A virtual environment is dependency isolation, not a filesystem sandbox.

The wrapper creates a new uniquely named folder containing five fictional JSON inputs and retains it. The planner creates no files. If you redirect stdout or save diagnostics, you create those private output files yourself. Existing fixture directories are not reused or overwritten. Review and manage your own retained fixture folders deliberately.

Use only authorized inputs. They may identify infrastructure or people through content, paths, player counts, states or observations. Structural validation and fixed CLI errors are not anonymization, backup verification, operational permission or public-release clearance. Library tracebacks and raw diagnostic logs can contain source paths and native details.

Keep actual plans, observations, endpoints, credentials, saved stdout, logs and environments private. Use stable quiescent files; sampled handle/metadata checks do not protect against every concurrent mutation or establish ACL privacy. The tool does not perform a maintenance action, probe a service or register a schedule.
