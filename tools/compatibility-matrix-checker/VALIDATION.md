# Validation and interpretation limits

configuration-compatibility-checks qualifies Python 3.12/3.13 on Windows and Ubuntu.
Native read/hash, fresh write/readback, hardlink-input refusal, linked-parent refusal,
changed-input detection and overwrite refusal are required. Only opposite-platform
methods may skip; local volume skips are not native proof.

Known-answer and adversarial checks cover exact fingerprints, ordered overlays,
explicit override refusal, delete/re-set, absent deletion, required final keys, no
default insertion, empty optional scopes, layer/key ambiguity and stale references;
added/removed/changed contract fields, header-only changes, conflicting snapshot
identity, empty definitions, exact attribute names and bounded field collections;
symmetric pair normalization, reverse duplicates/aliases, missing/false decisions,
unrequested stale rules, full component/version bindings and non-boolean decisions;
explicit/no-op/short/discontinuous/cyclic migration paths, exact selectors, nested
contract rejection, one selected revision per ID, adapter/check shapes and aggregate
field/check bounds. Identity cohorts test complete duplicate/conflict/rejected-row
accounting; strict JSON/I/O fixtures preserve source-tree and no-overwrite boundaries.

Collection acceptance copies each complete tool independently, verifies source manifests,
runs actual CLIs, creates fresh reports, refuses source/overwrite output, checks fixed
errors/raw-input pins/unchanged inputs and no action artifacts. Connected fictional HVAC
acceptance links overlay and baseline contract pins to a metadata diff, exact declared
component pair and explicit adapter path. Review counterexamples never gain qualified
scope pins. A separate game example uses invented build metadata. An explicit test
supplies fictional values to the existing public Configuration Contract Checker and
checks an out-of-range rejection; fingerprints are not decoded or treated as values.

No tests establish real configuration correctness/completeness, runtime compatibility,
adapter bytes, migration outcomes, policy suitability, privacy, rights or authority.
Original private implementations, customer/user records, schemas, policies, paths,
credentials, addresses and operational details were not selected. No actual settings,
installs, adapters, checks or migrations are performed by the new tools.
