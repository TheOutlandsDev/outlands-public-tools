# Standalone saved APK-metadata source-download qualification

## Scope and accepted records

The source ZIP requires eight fresh Windows/Ubuntu lanes on exact CPython 3.12.16, 3.13.18, 3.14.10 and 3.15.2. Each selects 91 methods: 61 original methods and 30 copied-runtime methods, totaling 728 selections. These are required selections, not assumed pass counts. The [release validation asset](https://github.com/TheOutlandsDev/outlands-public-tools/releases/tag/apk-report-diff-v0.1.0) supplies accepted outcomes, exact skips and source revisions.

Python is supplied separately. The recipe verifies SHA-256 and lengths of locked standalone distributions from build release 20261110, extracts into new owned prefixes and measures the actual executable version/hash before binding evidence to selected source. It does not install globally or change persistent PATH. Native-binary reproducibility is not claimed. No third-party Python package, AAPT2, SDK, APK or external producer is required or bundled.

## Preserved original suite and code

The 61 original methods comprise 43 comparison/CLI cases and 18 first-party safeguards, with 105 assertion calls: 103 in test methods and two in seven supporting helpers. Three runtime/generator files, both original test files, 22 runtime definitions and one generator definition retain raw bytes and parsed definition/method/helper bodies against the reviewed base. No production mirror, parser replacement or version rebinding is introduced.

A test-only adapter rejects undocumented skips and narrows broad operating-system skip paths. Applicable hosted links/hardlinks are mandatory. Exact opposite-platform cases and actual local Windows error 1314 limitations are recorded by test ID/reason, separately from passes. Arbitrary errors, empty discovery, wholly skipped groups and failures/errors do not qualify. Native cases cover Windows stream syntax and POSIX special-file refusal.

## Copied runtime and saved-text boundary

Additional tests copy the actual comparison runtime, support and fictional generator to an external owned location and invoke the real Python CLI. They check equal/six-change comparisons, exact strings, unsupported/duplicate declarations, unknown unmatched holds, relative common-library order, different/unresolved package identities, fixed status/count/error stdout and stderr, input immutability, output refusal, native paths, bounds, escaping and manifests. Source SHA-256 entries are independently checked against the exact selected text bytes; they are not APK hashes.

Default reports omit literal values, while requested details enable supported package/library identities and values. The `details_included` field must reflect each requested mode. Removing only opt-in literals must leave the same comparison observations. Raw unsupported rows and ignored application labels remain absent in both modes. Omission is not anonymization: hashes and structural observations can identify material. Ambiguous/unsupported comparisons remain holds, not confirmed unchanged fields.

No APK is opened, no AAPT2/SDK is installed or invoked, no capture is performed, and no app/device/signature is inspected by qualification. Saved text cannot prove capture authenticity, completeness, producer acceptance, full manifest validity, permission risk, malware absence, signing, installability or compatibility. Recognized ignored rows are discarded without assessing their contents. The unchanged optional [capture guide](CAPTURE.md) remains a separate manual workflow, not executed acceptance evidence.

## Fresh archive and release gates

Each lane independently rebuilds deterministic source ZIP/build-manifest bytes from exact reviewed Git source, checks every source-manifest row and archive member, and extracts into a new external owned directory. Safe relative names, exact inventory, regular-file modes, fixed timestamps and UTF-8 source payloads are checked. The source ZIP contains 30 reviewed source files plus their manifest, 31 members, excluding APKs, captures, runtimes, producer binaries, generated reports and raw logs.

A fresh application environment has no pip and zero installed distributions. Actual imports/tests must resolve from extracted source, and interpreter/runtime bytes must remain unchanged before/after. Assertion-based helpers refuse optimized Python. Every selected original/copied method must succeed subject only to finite recorded native skips. Retained source-suite jobs use measured interpreter fingerprints and canonical owned fixture roots; source/test invocations remain available.

Review exact source/privacy findings against a finite allowlist and dispositions. Publish only the ZIP, usage guide, public validation JSON, build manifest and checksums. Download all five assets anonymously, compare byte counts/hashes and exact tagged source, then run the downloaded source in another fresh environment. A consumer run without a reference rebuild records that omission instead of claiming identical-build evidence.

## Executed fictional guide and limits

The [walkthrough](../USAGE.md) runs 17 cases: three exit 0 outcomes, eight expected review exit 1 outcomes and six controlled incomplete/refusal exit 2 outcomes. Ten report manifests/twenty report-file hashes and twenty saved-text source observations are independently checked, with twelve unchanged fixtures and 42 exact input/report files. Six reports use private defaults and four enable details, including escaped literal version text. The detailed/default six-change pair produces identical comparison observations after removing only opt-in literal fields.

The unchanged [format](FORMAT.md), [historical validation](VALIDATION.md), [provenance](PROVENANCE.md) and [capture guidance](CAPTURE.md) define the subset and evidence boundary. Selected findings and text hashes do not establish APK content, app safety, signature validity, producer/capture authenticity, runtime compatibility or redistribution rights. Trusted stable input paths and output parents remain required; sampled path/handle identities and cooperative limits are not an OS sandbox, atomic snapshot or hard native I/O deadline. Output errors can leave partial new reports.
