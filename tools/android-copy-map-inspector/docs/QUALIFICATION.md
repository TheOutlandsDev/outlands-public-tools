# Standalone declared copy-map source-download qualification

## Required matrix and accepted records

Qualification requires eight fresh Windows/Ubuntu lanes on exact CPython
3.12.16, 3.13.18, 3.14.10 and 3.15.2. Each selects 65 methods: 35 preserved
original methods plus thirty copied-runtime methods, totaling 520 selections.
These are required selections, not assumed passes. The [release validation
asset](https://github.com/TheOutlandsDev/outlands-public-tools/releases/tag/android-copy-map-inspector-v0.1.0)
records actual outcomes, finite skips, interpreter facts and source revisions.

Python is separately supplied. The recipe verifies SHA-256/lengths of locked
standalone distributions from build release 20261110, extracts to new owned
prefixes and measures actual executable version/hash before source-bound
acceptance. No global install or persistent PATH change is performed. Native
binary reproducibility is not claimed. No Python package, Make/AOSP tool,
actual vendor config, payload or device is required or bundled.

## Preserved original code and native safeguards

The 35 original methods comprise eighteen copy-map/CLI cases and seventeen
support cases, with 58 assertions: 57 in tests and one in four supporting helpers.
Three production/generator files and both original test files retain raw bytes
and parsed bodies against the reviewed base, including 24 runtime top-level
definitions and one generator definition. The older `text_support.py` API stays
unchanged. No production mirror or parser replacement is introduced. Historical
format/provenance/validation documents and the examples README remain unchanged.

A test-only adapter narrows broad native skips and rejects undocumented ones.
Windows records the POSIX FIFO test; POSIX records the Windows alternate-stream
syntax test. Only actual local Windows privilege error 1314 may explain the
optional support symlink skip. Applicable hosted link/hardlink cases are mandatory.
Exact IDs/reasons stay separate from passes. Empty discovery, wholly skipped
groups, arbitrary errors and failures cannot qualify.

## Copied runtime, roots roles and declared conflicts

Additional tests copy the actual inspector, text support and fictional generator
to an external owned location and invoke the real CLI. They check literal append
and continuation handling; explicit leading roots; missing/nested/embedded
expression coverage; no defaults or environment substitution; unresolved entries
excluded from collision pairing; duplicate/source/owner conflicts; NFC/casefold
and file/parent portability candidates; conditional/include/reassignment coverage;
private defaults/details; exact opaque IDs/statuses/errors; independent
Make/roots/report hashes; manifests; bounds; immutable inputs; fresh reports and
native path/alias safeguards.

Only supported literal appends are indexed. Other Make statements require
coverage; later appends and both conditional branches may remain candidates.
No branch, include, assignment order or effective copy result is evaluated.
Only whole leading uppercase variables use explicit literal JSON substitutions.
There are no environment roots, guessed partition defaults or recursive/nested
expansion. Declared source/destination paths are text and are never accessed.

Only fully resolved entries participate in pair comparisons. Same source,
destination and owner produce a duplicate; differing source/owner at the same
destination produces a declared conflict. NFC normalization followed by casefold
or a slash-boundary prefix produces portability/file-parent candidates. This
does not verify actual filesystem case policy, file types or evaluated collisions.
Pair counts and deduplicated finding locations differ legitimately. Dense pair
sets fail at a collection limit rather than silently truncate.

The `--file` Make set has its own 32-file, 1-MiB-per-file, 4-MiB aggregate and
same-file/hardlink-duplicate checks. Optional roots JSON is a separate snapshot
with a 64-KiB limit and strict schema/structure/root-value bounds. It is outside
the Make set's count/aggregate/identity checks; no cross-role alias refusal is
claimed. Source and roots hashes are recorded separately.

Defaults omit declared/resolved paths and owner values. Requested details add
those selected fields, including unresolved text/null resolutions. Removing only
opt-in fields and the mode flag leaves the same observations. Opaque IDs,
hashes, positions, counts and conflict structure can identify material: omission
is not anonymization. Hashes/manifests prove selected-byte consistency, not
authenticity, source availability, evaluated output or redistribution rights.

All eight scope facts remain false: `make_evaluated`, `payload_paths_accessed`,
`payloads_copied`, `environment_roots_read`, `real_device_configs_used`,
`effective_build_results_verified`, `source_availability_verified`,
`payload_rights_verified`. No actual config, payload, device, complete build or
licensing acceptance is certified. Empty/empty-append scope may exit 0.

## Fresh archive and release gates

Each lane independently rebuilds deterministic ZIP/build-manifest bytes from
reviewed Git source, checks every source-manifest row/member and extracts into
a new external owned directory. Safe relative names, exact inventory, regular
file modes, fixed timestamps and UTF-8 source payloads are checked. The ZIP has
29 reviewed source files plus their manifest, 30 members. It excludes runtimes,
actual configs/payloads, generated reports and raw validation logs.

Fresh application environments have no pip and zero installed distributions.
Imports/tests resolve to extracted source; interpreter/runtime bytes stay
unchanged before/after. Assertion-based helpers reject optimized Python. Every
selected original/copied method must pass subject only to finite recorded
native skips. Existing configuration source commands and sibling Init native
lanes remain, with measured interpreter fingerprints and canonical owned fixtures.

Source/privacy findings require exact finite dispositions. Publish only the
source ZIP, usage guide, public validation JSON, build manifest and checksums.
Download all five anonymously, compare lengths/hashes and tagged source, then
qualify downloaded source in another fresh environment. A consumer without a
reference rebuild records that omission explicitly.

## Executed fictional guide and limits

The [guide](../USAGE.md) runs thirty cases: eight successes, nine reviews and
thirteen controlled incomplete/refusal results. Sixteen normal manifests,
32 report-file hashes, seventeen Make-input hashes and three roots-file hashes
are independently checked. Twenty-two fixtures stay unchanged and the workspace
has exactly seventy input/report files. Eight reports use defaults and eight
enable details. Three pairs preserve observations after removing only opt-in
fields/mode; child-only environment root traps are ignored as expected.

The unchanged [format](FORMAT.md), [historical validation](VALIDATION.md) and
[provenance](PROVENANCE.md) retain their earlier evidence boundaries. Trusted
stable inputs and owned parents remain required. Snapshot/path checks and
cooperative limits are not an OS sandbox, atomic snapshot or hard native I/O
deadline. Output failure can leave partial new reports; preserve/review them and
select new destinations after fixing the cause.
