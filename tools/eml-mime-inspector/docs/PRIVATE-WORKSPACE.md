# Private EML workspace

Keep explicitly selected stable regular EML inputs and generated reports in a directory you control outside the source checkout or extracted source. The release uses only invented example.invalid messages. There is no mailbox discovery, provider adapter, sending, remote resource following, body rendering or attachment extraction.

The inspector supports a deliberately narrow CRLF/7-bit MIME subset with explicit headers, types and encodings, canonical base64 and bounded structures/decoded text. Many ordinary messages are refused. Structural acceptance and hashes do not establish message authenticity, attachment safety, delivery, anonymization or rights to share content. Default output omits bodies, header values and filenames but sizes, hashes and structure remain identifying.

Choose an existing trusted parent and a fresh output filename. Native file checks require ordinary single-link inputs and trusted quiescent ancestors. Output is exclusively created and never replaces an existing file. Failed writes may retain unconfirmed partial output; preserve it and choose a new destination. Windows inherits parent ACLs. Parser/resource bounds and sampled file checks are not an OS sandbox, hostile-filesystem containment, an atomic snapshot or hard execution deadline.

The release contains original MIT source, fictional generation methods, tests, runtime pins and reproducible packaging/qualification methods. Obtain CPython separately. No interpreter, actual mail, attachment payload file, account configuration, operational report, raw log or credential is bundled.
