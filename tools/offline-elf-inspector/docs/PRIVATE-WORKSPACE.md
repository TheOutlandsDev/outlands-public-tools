# Private ELF inspection workspaces

Use an existing trusted private parent outside the source checkout and public/synchronized folders. Every generated demo/report path must be new. The guide creates invented metadata and padding only; it copies no actual application, phone image, firmware or proprietary library.

The inspector reads selected ELF metadata as bytes. It never loads or executes an inspected file, follows a runtime hint, runs a device/flash command or uploads results. The qualification-only compiler/readelf oracle is separate from ordinary use; its disposable authored libraries are also never loaded or executed.

Root/entry labels replace selected absolute input paths, but reports still contain relative filenames, SONAME/NEEDED names, hashes and embedded interpreter/RPATH/RUNPATH strings. Opt-in hints can add embedded library, configuration and firmware tokens. Those fields may identify a project or device context. Neither mode is anonymization or permission to publish. Keep real inputs, reports, manifests, paths and raw diagnostics private, and review sharing separately.

Default inspection does not scan runtime hints or emit their fields. Hint mode examines bounded ASCII bytes from the same selected ELF handles and searches no additional directory. An observation can be unused text or coincidence; absence can reflect encoding, construction, compression or limits. Hints do not add dependencies or prove configuration/firmware access.

Existing destinations/files are not replaced. Failed or cancelled output may retain an incomplete new private report folder. Preserve it for review and choose a different new name for a retry; the tool performs no cleanup or rollback. The manifest is an integrity record, not a signature or source backup.

Use one operator with stable trusted local storage. Native path/identity observations and cooperative budgets are best effort, not atomic snapshots, hostile-filesystem isolation or hard native I/O deadlines. Unsupported links can leave providers unseen. Do not infer universal ADS/hardlink/mapped-drive controls from these checks. No result establishes loader behavior, full ABI compatibility, device repair, phone/hardware compatibility or software licensing. Follow applicable permissions and workplace policy.
