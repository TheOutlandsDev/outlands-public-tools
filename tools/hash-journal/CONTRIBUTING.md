# Contributing

Suggestions and minimal reproductions are welcome through the collection's
Hash Journal issue forms. Describe the use case, source commit, OS/SDK and
expected versus actual behavior. Use original fictional event text; keep real
event logs, internal build details, names, credentials and private paths out of
public issues. Do not attach proprietary source or runtime binaries.

Changes need tests for supported format/limits, fresh-file behavior and
preservation of input files. Preserve the distinction between internal chain
consistency and separately trusted expected-head verification. New signing,
timestamp or retention features require their own explicit design and evidence;
fixture counts do not justify broader authenticity claims.

Run the documented harness on disposable data. Preserve existing license and
attribution notices. Contributions must be material you have rights to share
under the applicable project license; external runtimes retain their own terms.
