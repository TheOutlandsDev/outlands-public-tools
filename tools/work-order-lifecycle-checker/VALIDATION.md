# Validation and interpretation limits

The service-maintenance-checks workflow qualifies Python 3.12/3.13 on Windows and
Ubuntu using fictional HVAC declarations, exact source pins and mandatory native
file fixtures. Hardlinks and parent symlink/junction cases must execute. Only one
opposite-platform boundary method per tool may skip; local volume skips do not
establish native qualification.

Known-result and rejection cases cover explicit old/new reset boundaries, nonzero
counter baselines, exact segment sums, ties, orphan/decreasing/conflicting readings;
time/usage equality, combined criteria, stale uncertainty, future/pre-service snapshots,
unit/origin mismatches, time-only plans and signed distances; exact contiguous order
revisions, valid nonterminal prefixes, hold/resume/cancel, terminal refusal and
snapshot pins; task/evidence/parts requirements, missing/ambiguous records, exact
revision/pin checks, parts conservation, empty requirements and the total budget.

Standalone CLI acceptance copies every complete tool directory independently,
checks source pins, runs examples, creates new reports, refuses overwrite/source-tree
output and checks fixed errors, input hashes, no input mutation and no target artifacts.
The connected four-tool exercise carries an invented blower counter across a reset
to twelve demo-cycles, selects a due-at-twelve usage interval, explicitly supplies
an operator-chosen order history and reviews two done tasks, one installed/one
returned filter and an invented evidence pin against the exact completed revision.
A negative case proves a completed order can still fail task/parts completion checks.
There is no automatic scheduling, work selection or hidden integration.

These synthetic functional checks do not establish physical meter truth, suitable
intervals, complete history, authentic work/evidence, actual parts, operator authority,
production readiness, equipment safety or future data privacy/publication rights.
The narrow state protocol is newly invented, not a private workflow reconstruction.
No device, schedule, order, stock, service state or original private program is
modified. Existing public I/O requires trusted storage and does not sandbox hostile
concurrent processes. Real operator data and generated reports remain private.
