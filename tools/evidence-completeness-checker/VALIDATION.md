# Validation and interpretation

The test-regression-checks workflow qualifies Python 3.12/3.13 on Windows and Ubuntu.
Native hardlink, linked-parent, changed-input, fresh-file and overwrite fixtures are
required. Only opposite-platform methods may skip; local volume skips are not native proof.

Known-answer/adversarial tests cover normalized expected-result material, missing/stale
contracts and aliases; exact output/exit matching, expected nonzero exits, missing and
ambiguous results, all noncompleted states, truncated captures and run/subject pins;
directional regression/improvement, persistent mismatches, changed contracts, added/
removed cases, incomplete comparisons and reused run IDs; missing/truncated evidence,
cross-run/case/result/policy bindings and complete failure evidence without verdict
upgrades. Every identity list checks complete duplicate/conflict/rejected-row accounting.
Pinned public JSON/I/O helper tests retain source-tree/overwrite/fixed-error protections.

Actual standalone acceptance copies each tool independently, verifies source manifests,
runs examples, writes fresh reports, refuses overwrite/source output, checks raw-input
pins/fixed errors and verifies no input mutation or action artifacts. A connected invented
HVAC air-handler exercise checks a case manifest, reconciles a matching baseline, flags
a candidate mismatch as regression, and explicitly binds complete failure evidence to
that candidate result. A cancelled observation remains incomplete across run, comparison
and evidence reports. Game quest metadata contains no assets or executable checks.

Only supplied fictional metadata is analyzed; no supplied Python test or original
application is executed. These checks do not establish real executions, correct test
expectations, real-world coverage, evidence authenticity, privacy, rights or production
suitability. Original private code, cases, policies, customer/user records, paths,
credentials, operating details, third-party assets and raw output were not selected.
