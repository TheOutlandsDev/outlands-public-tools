# Validation and interpretation limits

The quality-inspection-checks workflow qualifies Python 3.12/3.13 on Windows and
Ubuntu with exact source pins, invented HVAC inputs and mandatory applicable native
file fixtures. Hardlink and parent symlink/junction cases must run. Only one opposite-
platform boundary method per tool may skip; local volume skips are not native proof.

Known-result and rejection cases cover exact decimal bounds, normalized duplicates,
ambient Decimal-context independence, open/closed endpoints and point intervals;
selected rule versions and ambiguous measurement pairs; Cartesian inspection scope,
missing/unevaluated/outside records, declared pins, pair bounds and conflict withholding;
cohort denominator accounting, pending states, scrap-only reconciliation and no rework
double-counting; complete attempt sequences, repeated repairs, wrong attempt numbers,
ties, orphan events and whole-cohort withholding for incomplete histories.

Actual standalone CLI acceptance copies each tool independently, verifies source pins,
runs examples, creates fresh reports, refuses overwrite/source-tree output, and checks
fixed errors, input hashes, no input mutation and no target-action artifacts.
The connected four-tool exercise explicitly selects separate before/after readings:
one unit passes first attempt, one has a declared repair then passes, and one is
declared scrap after an outside reading. Final inspection records are complete but
still include an outside outcome. Valid histories derive one first-pass good, one
reworked good and one scrap: first-pass 1/3 and eventual yield 2/3. A negative case
proves reconciled yield declarations cannot establish missing inspection coverage.

These synthetic functional checks establish the documented narrow contracts, not
real measurement accuracy, calibrated limits, actual repairs, complete populations,
authentic evidence, private-data clearance, approved routes, equipment suitability,
production readiness or permission to publish future data. No process is operated
and no record, setting, stock, work order or disposition is changed. Existing public
I/O requires trusted storage and does not sandbox hostile concurrency.
