# Provenance and license scope

Offline Backup Chain Checker is a fresh neutral full/incremental relationship
convention using newly authored fictional metadata. Its sampled bounded input
reader adapts this collection's public MIT retention-checker pattern at commit
`dd49bf02674394004111b6df37743dbf53c5d42d`, with original-path suffix validation
already added in the existing checker. It is not a vendor-format import or
proof about an operational backup set.

The runtime and four JSON examples retain exact Git bytes from baseline
`a9a43c12dd6e4214655cd79b1a10f00f6dba2905`. The runtime already displayed version
0.1.0. No graph/result, timestamp, retention-policy or input-path repair is
introduced by standalone packaging. Source attributes preserve reviewed bytes;
no normalization is used to make protected hashes pass.

All 43 original test method bodies, 105 assertion calls and eight original
helper ASTs remain preserved. Explicit `python-ast-fields-json-v1` encoding
retains complete AST fields for stable hash comparison across supported Python
versions, without weakening within-version original/adapted equality. The
adapter selects the actual extracted checker/script directly; no runtime
mirror, public sibling import, donor or duplicate checker is shipped.

Selected original source, tests, examples and docs retain the full
[MIT license](../LICENSE) and TheOutlandsDev identity. Standalone preparation,
qualification, documentation and authored fictional consumers used AI
assistance, without exclusive-authorship claims. Python/standard-library and
OS mechanisms retain their own terms and are not bundled as binaries. The
license grants no rights in operator inputs or third-party backup material.

No held original server/backup source, private inventory, configuration,
operational record, credential, user identifier or actual backup is selected,
read, copied or executed. Only authored fictional graph metadata ships here;
real controls/results and operational evidence remain private. Unrelated
historical rights remain uncleared.

Declared full/incremental relationships and sequence fields do not establish
snapshot existence, independence, content/parent agreement, authenticity,
completeness, encryption access, application consistency or restorability.
Metadata-derived order is not a restore command or deletion permission. IDs,
issue relationships and dependency order can remain identifying even though
series, sequence and parent fields are omitted from results.
