# Validation and limits

Run from the module folder with CPython 3.12 or newer:

```text
python -B -W error -m unittest discover -s tests -v
python -B source_check.py
```

The reviewed local Windows/CPython 3.12.7 suite discovers 52 methods: 34
planner/example/CLI methods and 18 copied first-party safeguard methods. The
local restricted environment passes 46 with six platform/link-creation skips.
Skips are not passes; Windows/Ubuntu CI provides separate platform results.
The initial fixture expectation for a control character was corrected to match
the earlier strict JSON text rejection; no input guard was relaxed.

Fixtures cover exact full-source hash/size, expected slice checks, wrong sources,
out-of-bounds declarations, overlap/repeated/adjacent/unsorted edits, no-ops,
hex grammar, strict JSON types/duplicate keys/limits, deterministic candidates,
private stdout/reports and report hashes. Actual CLI tests exercise preview,
explicit separate application, review, invalid inputs and overwrite refusal.

Application tests cover existing report preflight, existing candidate/input
aliases, missing/linked/traversal parents, exclusive-create races, Windows
reserved/ambiguous naming, source byte limits and input preservation. Simulated
flush failure, readback mismatch and later report-write failure verify that no
successful receipt is reported and no source is changed. New incomplete files
are preserved for caller review; tests do not claim transactional rollback.

Fixtures are disposable generated bytes and invented plans only. Tests never
patch a real game/firmware, execute a generated candidate, decode a protected
format, contact a network, mount an image or perform a device operation. A
successful plan does not prove compatibility, safety or intended behavior.

When a sandbox's default temporary folder is unavailable, set `TEMP` and `TMP`
to an existing writable private workspace before running tests. Each test owns
and cleans a temporary directory. Source inventories remain outside that data.
