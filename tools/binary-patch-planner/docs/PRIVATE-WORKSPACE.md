# Private fictional-byte workspace

Use stable regular local source and plan files in an existing private directory outside the extracted source. Default preview calculates a candidate in memory and writes reports only. Explicit --apply-output selects a separate new candidate file. The source and plan are never intentionally rewritten. A wrong source size/hash or expected-byte mismatch withholds application. Invalid, overlapping or out-of-bounds plans fail explicitly.

Reports omit payload bytes and local filenames, but hashes, offsets and layout can identify material. This is data minimization, not anonymization. Keep real inputs, plans and identifying reports private. Qualification uses generated bytes and fictional plans only; candidates are never executed. No real game, firmware, protected format, physical device, compatibility or runtime behavior is tested.

Use a parent you control and a new path for every output. Link/alias/path checks, exclusive creation and readback are not an OS sandbox, hostile-filesystem transaction, atomic snapshot, power-loss durability guarantee or transactional rollback. A write, flush, readback or later report failure can leave a new partial or complete candidate without a successful report. Preserve and review that artifact; select a fresh destination after correcting the cause. No automatic cleanup or source patching is promised.

The release includes original MIT source, authored tests, fictional generators and qualification methods. Obtain CPython separately. No interpreter, generated binary, real patch plan, game/firmware file, operational report, raw log, credential or third-party implementation is bundled. Unsigned source/report manifests and matching hashes establish byte consistency within their scope, not authenticity, ownership or safe runtime effects.
