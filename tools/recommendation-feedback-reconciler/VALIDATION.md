# Validation and evidence limits

The dedicated forecast-feedback-checks workflow runs Python 3.12/3.13 on Windows
and Ubuntu: source manifests, invented core cases, shared numeric/row contracts,
required native file boundaries and actual independently copied CLI workflows.
Required hardlink and symlink/junction fixtures must run; only the opposite-platform
method per tool may skip. A local selected-volume link-creation skip does not
qualify that native boundary; the CI matrix must exercise it.

Known-result cases check exact fractions, large squared errors, RMSE rounding,
inclusive interval endpoints, zero-width intervals, fixed-bin boundaries,
outside/unknown/missing accounting, TVD 0/1/one-half, exact revision binding,
pending/orphan/conflicting feedback and all-row accounting. Invalid cohorts
withhold derived summaries; body values are omitted from default reports.

Actual CLI acceptance copies each tool independently, verifies source pins,
creates new reports, refuses overwrite/source-tree output, retains pending
states, checks raw input hashes and preserves input files. A connected four-tool
cohort uses the existing public baseline's actual invented predictions; no private
original code, model or data is run. No native target action, model training,
provider connection, deployment, browser app or publication adapter is included.

These are synthetic functional checks, not real deployment accuracy, interval
calibration, independent samples, drift detection power, causal attribution,
representative datasets, authenticated feedback or a universal security review.
Source/label/clock authority is not established. OS resource quotas and hostile
local-process isolation are not provided. Real inputs/reports remain private;
whole-drive and original-family privacy/rights clearance remains incomplete.
