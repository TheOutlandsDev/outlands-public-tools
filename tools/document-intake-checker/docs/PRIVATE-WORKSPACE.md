# Private Document Intake workspace

Select a stable regular DOCX and an explicit trusted mapping in a private directory outside the source. Accepted records, identity values, source rows, mapping declarations, fingerprints and counts can identify private data. Default output already includes accepted values. A review-required batch can retain individual accepted rows; consumers must enforce the whole-batch ready_for_explicit_review gate. That gate is not a business approval, import or authority check.

The supported stored-text DOCX subset is deliberately narrow. No Office process, network resource, database import or rendering is performed. Input ZIP parts are read in memory, never unpacked to files. Verified source-ZIP qualification extraction is separate. Boundaries are cooperative application limits, not an operating-system sandbox or hostile-writer containment.

Use fully spelled paths, trusted quiescent ancestors and a fresh external report name. Linked and multilink routes are refused. The Windows create-new/reparse-point correction refuses existing entries, including dangling leaves. Failed writes may leave unconfirmed partial output: retain it and choose another name. Windows permissions inherit from the parent. No raw input, generated report, SDK, account, credential or private evidence belongs in the source release.
