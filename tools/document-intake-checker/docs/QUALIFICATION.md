# Document Intake Checker qualification

Version 0.1.0 selects 32 source/documentation files plus `SOURCE-MANIFEST.json` (33 source ZIP members). Obtain Python separately. No original DOCX, generated report, Python binary, private mapping, operational record or raw evidence log is bundled. Generic methodology is included in [METHODOLOGY](METHODOLOGY.md).

The required matrix is Windows and Ubuntu with CPython 3.12.16, 3.13.18, 3.14.10 and 3.15.2. [PYTHON-LOCK.json](../PYTHON-LOCK.json) pins complete python-build-standalone archives from the 20261110 recipe. Each lane verifies the archive, selected executable version/hash and preparation identity, creates a fresh environment without pip and checks zero installed distributions. It imports a copied source archive outside the checkout and compares an independent rebuild's ZIP/build-manifest bytes.

Each lane selects all 53 originals (23 DOCX core, eight typed document-intake and 22 native/buffer-boundary methods) plus exactly 30 copied-runtime CLI methods: 83 selections per lane and 664 across eight lanes, comprising 424 original and 240 copied selections. Pass/skip/failure/error totals are measured from actual receipts and are not inferred from selection counts. Original test bodies remain unchanged. The source contains 85 assertion call sites and three test helpers; the native preservation record binds their actual syntax and bytes.

The runtime contains 63 non-generator top-level definitions and two generator definitions. Five runtime/generator files and the original test/historical record files remain byte-identical to the selected baseline. Only Windows `native_windows.exclusive_write` changes, porting the qualified EML/DOCX safeguard: reject existing leaf entries before exclusive `CreateFileW` creation with reparse-point handling and explicit handle/fd ownership. Fixed generic CLI error codes and retained partial writes are preserved. File/function/diff hashes declare this exception; full runtime byte preservation is false and preservation of the five other runtime files is true. No test is weakened to accommodate it.

Native hardlink and Windows junction fixtures are mandatory. Original tests allow only their exact opposite-platform cases. Copied Windows leaf-symlink qualification is mandatory in strict hosted lanes; non-strict local acceptance permits only the selected exact privilege error 1314 and matching provenance. Hardlink, junction and supported POSIX-link errors cannot become optional skips. Actual selected, started and successful test IDs, skip membership/reasons and named positive flows are checked. Setup/negative controls are separate observations.

The copied suite exercises actual script entrypoints and public-writer interchange using fictional values, with mapping/header exactness, duplicates, identity conflicts, conversion errors, whole-batch readiness, privacy limits, immutable sources, native I/O refusals and output retention. The [executable guide](../USAGE.md) uses independently authored typed values, accepted groups and issue lists rather than importing the intake conversion/grouping implementation as an oracle. Its complete expected reports independently bind raw DOCX, mapping, normalized CSV and stored-content hashes, and every created file is inventoried.

The parser recipe measures actual Expat and compile/runtime zlib versions plus selected `xml.etree.ElementTree`, `_elementtree`, `pyexpat` and `zlib` module identities before/after qualification. Both `XMLParser` and `TreeBuilder` must use the selected C bindings. File modules belong to the selected Python prefix and are hashed; a true built-in module is bound to its interpreter executable. Whole archive pins provide a coherent SDK; records do not independently certify library builds, binary reproducibility or a universal library version. Ancillary original-source native receipts remain distinct from full archive parser/component measurements.

Required application scope flags remain false: `real_documents_used`, `document_properties_exported`, `external_resources_followed`, `document_executed`, `office_processes_started`, `archives_extracted`, `visible_layout_verified`, `general_word_compatibility_verified` and `production_workflows_verified`. Input DOCX decompression is in memory, with no filesystem unpacking. Packaging helpers do extract the verified source ZIP into owned qualification workspaces. `imported` and `source_transformed` remain false in preview reports. Positive `fictional_document_intake_flow_checked` and `native_file_guards_checked` flags require actual successful fictional/guard observations. Readiness is evaluated per batch and is not globally true or false.

Validation records contain the actual matrix totals, source and ZIP identities, selected interpreter/preparation records and measured parser metadata. Checksums establish byte agreement with the published record. They do not prove data authenticity, business approval, effective import, Word layout or production compatibility. Real documents, imports, business decisions and general Word interoperability remain unverified.
