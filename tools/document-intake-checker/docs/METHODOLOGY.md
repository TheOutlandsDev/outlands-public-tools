# Reproducing typed document-intake evidence

Use fictional files in an owned private workspace, with source code kept separately. Select one exact table and an explicit mapping. Parse supported stored DOCX body content first, then encode that table in memory as CSV for the retained public typed-intake rules. No temporary table file, header search or inferred business policy is required.

Author expected records as data rather than calling the implementation being checked. State each typed value, accepted group with source rows, rejected row/code and conflict group independently. Verify the full report, including accounting, batch status and readiness, rather than only checking a success marker. Compare raw document, mapping, normalized table and stored-block hashes independently. Canonical CSV/JSON serialization is a format operation; the intake converter and grouping functions are not used as expected-results oracles.

Keep accepted records separate from the whole-batch decision. The invariant is `input_rows = accepted_records + duplicate_rows + rejected_rows + conflict_rows`. Identical normalized records retain every contributing source row and count extras as duplicates. Conflicting valid identity groups contribute no accepted member. A rejected or conflicting row can coexist with a separate accepted record, while readiness remains false for the entire batch. An empty accepted set also makes readiness false. No downstream import or approval is exercised by this qualification.

Exercise explicit type grammar, optional blank/null versus zero, decimal normalization, exact booleans and valid dates. Preserve literal case and ordinary whitespace. Show that malformed mappings, duplicate headers, absent mapped headers, unknown-column policies and invalid table selections fail with fixed codes. Verify default previews expose accepted values and mapping details, while rejected/ignored payload markers and document properties are omitted. Omission and hashes do not anonymize real data.

Use all four independent generator variants and additional authored XML/ZIP fixtures. Separate stored text from rendering: opaque style/property parts are not evaluated, raw bytes can differ while stored content agrees, and unsupported content in an unselected table still causes refusal. Bounds are application checks. Do not run Office or input documents, follow external resources or unpack document members to files.

Invoke actual Python script entrypoints in copied runtime files under a fresh no-pip environment. Check C XML binding coherence and selected parser/compression identities. Snapshot inputs and all pre-existing workspace files before each operation; allow only explicitly expected new files. Verify native hardlink/path/output safeguards. A controlled write fault should retain and hash its unconfirmed partial output, then demonstrate that the destination cannot be reused silently. This is synthetic I/O evidence, not rollback, hostile-filesystem containment, atomic snapshots or power-loss durability.

Inventory every generated input, mapping, report, observation ledger and manifest. Keep independent source snapshots and interpreter/archive pins. Preserve working and committed-head proof identities separately. An unsuccessful or diagnostic preparation attempt must retain its actual evidence and cannot be relabelled as a later successful run. Publication records bind selected Git blobs, exact source ZIP members, all required CI receipts, checksums and anonymous asset readback. Generic reproducible methods are public; private paths, logs, records and operational mappings remain local.
