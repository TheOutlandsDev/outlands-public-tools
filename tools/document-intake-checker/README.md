# Document Intake Checker

Preview one explicitly selected DOCX table using a supplied typed mapping. The checker reports accepted records, identical duplicates, rejected rows and conflicting valid identities. It does not import records, approve a batch or modify the source document. The six included runtime/generator files use Python's standard library; no Office installation or Python package is required.

From this directory, generate an invented document at a new absolute external path and preview its selected table:

```text
python -E -s -B fictional_docx.py --variant before --out NEW_EXTERNAL_INPUT.docx
python -E -s -B document_intake.py --input NEW_EXTERNAL_INPUT.docx --table table-1 --mapping examples/mapping.json
python -E -s -B document_intake.py --input NEW_EXTERNAL_INPUT.docx --table table-1 --mapping examples/mapping.json --out NEW_EXTERNAL_REPORT.json
```

Use an existing trusted private parent outside the source directory and fresh output names. The `before` example has three data rows: two accepted records and one identical duplicate. The repeated identity preserves selected-table rows 2 and 4. The `needs-review` variant has two conflicting valid rows and one invalid integer, so it returns exit 1 with no accepted record. [USAGE](USAGE.md) provides an executable fictional walkthrough with independently authored complete expected records, issues and hashes. [METHODOLOGY](docs/METHODOLOGY.md) explains the evidence boundaries.

The default preview already contains accepted typed values, the supplied mapping and source-row provenance. It is not a body-omitting or anonymized summary. Invalid row payloads and ignored column values are omitted, but accepted values, field names, structure and hashes can identify a document. Keep previews and real mappings private. Property omission and JSON escaping do not establish confidentiality or rights to publish.

The mapping contract is [outlands-table-map-v1](examples/mapping.json). Each unique source/target field declares `text`, `integer`, `decimal`, `boolean` or `date` and an explicit required boolean. One to four required target fields define identity. Unknown columns require explicit `reject` or `ignore`. Headers are exact and selected from row 1 of the requested table; there is no header search, alias inference, trimming or automatic policy discovery.

Integer text must be canonical, with absolute value at most one trillion. Decimal text has at most six fractional places and the same bound; normalized decimal output is a JSON string, preserving exact decimal values without binary float conversion. Booleans are exact `true`/`false`. Dates must be valid `YYYY-MM-DD`. Optional blank strings become null; zero is distinct from blank. Text is limited to 256 characters and rejects controls. Case and ordinary whitespace remain literal.

Valid records group by the explicitly declared typed identity, in canonical encoded-key order. Equal normalized records retain all source rows while counting extra identical rows as duplicates. A valid identity group containing different records withholds every member as a conflict. Rejected rows contribute fixed diagnostic codes without their payloads. The invariant is `input_rows = accepted_records + duplicate_rows + rejected_rows + conflict_rows`.

Any row issue or an empty accepted set makes `ready_for_explicit_review` false. A review-required report can still contain accepted records; downstream code must enforce the whole-batch gate. A true gate means only this preview satisfied the supplied rules. It is not approval, import authorization, business correctness or production acceptance. `imported` and `source_transformed` remain false.

The DOCX wrapper feeds a bounded in-memory CSV representation of the selected stored table to the retained public intake core; no intermediate CSV file is written. Raw DOCX, extracted stored-block content, mapping bytes and normalized table bytes have distinct SHA-256 pins. Formatting, properties or ZIP transport can change raw bytes while retaining the same stored content. Table IDs follow document order; row provenance is one-based within the selected table, including its header. These are source positions, not stable business identities.

Only the narrow bounded Transitional WordprocessingML plain-text/rectangular-table subset is supported. All main-body content is checked, even unselected tables. DTDs, comments, processing instructions, unsupported active features, external relationships, direct hidden markers, nested/merged cells and malformed structures are refused. Known formatting/property parts can be bounded opaque bytes; they are not exported, interpreted or used to resolve resources. Styles, visibility, automatic numbering and Word's rendered layout are unverified. Ordinary DOCX files outside the subset may be refused.

Limits include 4 MiB per input, 64 ZIP entries, 2 MiB per expanded part/8 MiB total and 200:1 expansion ratio; parsed XML depth 32, 50,000 nodes and 2 MiB aggregate text/attribute characters; 2,000 top-level paragraphs, 32 tables, 1,001 rows per table, 32 columns, 20,000 total cells, 4,096 characters per paragraph/cell and 1 MiB total extracted text. Intake permits at most 1,000 data rows and 32 mapped fields. JSON output is limited to 8 MiB with refusal, not truncation. These are application bounds, not an OS sandbox or hard deadline.

The application decompresses DOCX members in memory without unpacking input archives to files. Packaging qualification separately extracts the verified source ZIP. No input is executed or rendered, no external resource is followed, and no Office process, mailbox, database or service is used. The retained core also contains CSV/XLSX routines; this standalone document wrapper selects its in-memory CSV path and makes no new XLSX compatibility claim.

The qualification recipe selects Windows/Ubuntu with pinned CPython 3.12.16, 3.13.18, 3.14.10 and 3.15.2. Its source ZIP selects 32 files plus the source manifest, without Python binaries, DOCX inputs, real records or generated reports. Actual matrix evidence is described in [qualification](docs/QUALIFICATION.md). Five runtime/generator files, all 53 original test bodies and the three historical documents remain unchanged. The sole runtime correction ports the published Windows `exclusive_write` fix, refusing existing leaf entries before exclusive native creation and preserving fixed generic errors. Historical byte-identity wording remains in the retained [origins](ORIGINS.md) and [I/O record](IO-SAFETY.md); this release explicitly records that exception.

Native file checks require trusted quiescent ordinary single-link inputs, including the mapping. New reports are exclusively created outside the source directory; existing or partially written outputs are retained and cannot be silently reused. Sampled metadata/hashes are not atomic snapshots, hostile-filesystem containment or full metadata preservation. POSIX requests mode 0600; Windows inherits parent ACLs without a confidentiality guarantee. See [original validation](VALIDATION.md).

Exit 0 means the preview passes its declared rules; exit 1 means review is required; exit 2 means invalid input/refused I/O; handled interruption returns 130. Fixed diagnostics omit supplied argument values and native paths. The library entrypoint is `document_intake.preview(docx_bytes, mapping_bytes, 'table-1')`; native CLI file protections do not apply automatically to a caller's own buffer-acquisition code.
