# Validation and interpretation limits

The ai-decision-checks workflow qualifies Python 3.12/3.13 on Windows and Ubuntu
using exact source pins, invented HVAC/game-event contracts and mandatory native
filesystem fixtures. Hardlink and parent symlink/junction cases must run; only one
opposite-platform method per tool may skip. Local volume skips are not native proof.

Known-result/rejection cases cover ordered prompt messages, role/text/field changes,
exact placeholder declarations and independent taxonomy revisions; rename/retirement/
introduction, split/merge ambiguity and complete mapping coverage; exact decimal
score/margin boundaries, lexical/abstaining ties, policy-consistent abstention,
non-probability vectors, wrong declarations and malformed cohorts; full-denominator
accuracy/abstention, exact fractional thresholds, signed regression deltas, identity/
scope pins, abstention-inclusive counts and withheld partial-cohort pins.

Standalone CLI acceptance copies each complete directory independently, verifies
source pins, runs invented examples, creates fresh reports, refuses overwrite/source-
tree output and checks fixed errors, raw input pins, no input mutation and no target
artifacts. The game fixture preserves a quest label and a tied-score abstention.
The connected HVAC exercise compares a changed prompt, verifies taxonomy pins through
an explicit one-to-one mapping, reproduces two labels/one abstention, and compares
candidate accuracy 2/3 against baseline 1/3 on a declared three-case cohort. The test
explicitly adapts invented baseline labels into the selected comparison taxonomy;
the runtime mapping checker never migrates datasets. A stricter gate rejects the
same policy-consistent candidate. No classifier or provider is invoked.

These are synthetic functional checks of narrow declarations, not authentic prompt/
artifact bytes, truthful labels, private-data clearance, model behavior, calibrated
confidence, independent holdouts, statistical significance, production suitability
or deployment authority. Original private source, prompts, label policies, records,
configuration and assets were not consulted or selected. No inference, training,
dataset relabeling, provider delivery or deployment is performed by these tools.
I/O guards require trusted storage and do not sandbox hostile concurrent processes.
