# Validation and interpretation limits

The scheduling-scenario-checks workflow qualifies Python 3.12/3.13 on Windows and
Ubuntu. Native hardlink, linked-parent, changed-input, fresh-file and overwrite fixtures
are required. Only opposite-platform methods may skip; local volume skips are not proof.

Known-answer/adversarial tests cover interval union/subtraction/conservation, clipping,
outside closures, normalization, zero-width/overlap rejection and bounded calendar/
intersection report growth; exact predecessor pins/lags, release lower bounds, due misses,
duplicate endpoint ambiguity, disconnected cycles and an iterative 700-task chain;
half-open working windows, missing placements/predecessors, release/deadline/lag violations
and plan pins; signed scenario deltas, additions/removals, changed contexts, incomplete
coverage, different selected calendars, visible lateness and withheld aggregate totals.
Every identity list checks duplicate/conflict/rejected-row accounting and scope withholding.
Public JSON/I/O helper tests preserve source-tree, overwrite and fixed-error protections.

Actual standalone acceptance copies each tool separately, verifies source pins, runs
fictional examples, writes fresh reports, refuses overwrite/source output, checks raw
input pins/fixed errors and verifies unchanged inputs/no action artifacts. A connected
invented HVAC flow subtracts a working-window closure, checks precedence-only lower
bounds, explicitly adapts proposed availability into a new calendar revision, checks
placements and compares a complete candidate. A missing task blocks aggregate deltas.
The collection-level exercise explicitly adapts placements to the existing public
Resource Reservation Conflict Checker, confirming a one-unit plan and an over-capacity
counterexample separately; the new tools never claim capacity_checked. A game-build
availability fixture contains no assets or executable build commands.

These synthetic checks do not establish genuine availability, task durations, complete
constraints, physical capacity, actual completion, optimality, data privacy, rights,
production suitability or dispatch authorization. Original private code, schedules,
records, policies, paths, credentials and operating configuration were not selected.
