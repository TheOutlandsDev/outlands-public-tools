# Validation and limits

The knowledge-context-checks workflow qualifies Python 3.12/3.13 on Windows and
Ubuntu. It runs exact source manifests, synthetic core contracts, malformed JSON,
complete duplicate/conflict/rejection accounting, all applicable native file
boundaries and actual standalone CLI workflows. Native hardlink and parent
symlink/junction fixtures are mandatory in CI; only the opposite-platform method
per tool may skip. Local volume limitations are recorded and are not native proof.

Known-result tests cover dependency order/cycles, maximum graph depth without
recursion, source/revision mismatches, exact fixed windows and global chunk caps,
Unicode code points versus UTF-8 byte counts, unchanged CRLF/combining characters,
precision/recall/MRR fractions, missing judgments, short and empty rankings,
duplicate rank refusal, exact span bounds/quotes and global withholding after any
issue. An unrelated answer can PASS quote integrity while truth/support flags
remain false; that limitation has an explicit regression case.

The collection walkthrough copies every tool independently, checks source pins,
executes fictional examples, verifies new report/overwrite/source-tree refusals,
fixed errors, unmodified input pins and omission of document/answer/quote bodies.
A connected four-tool cohort passes actual planned chunk offsets/pins into a
citation check and compares actual manifest/retrieval outputs with known results.
No external search/model/provider, original data/application or training asset
is used. No GUI, browser service, index, chunk-file export or target update exists.

These are synthetic functional checks, not representative retrieval quality,
semantic chunking, tokenizer compatibility, model safety, claim entailment,
factual truth, authenticated provenance, publication rights or a universal privacy
guarantee. Keep actual inputs/reports private. Native guards require trusted,
quiescent storage and do not sandbox hostile concurrency or impose OS quotas.
