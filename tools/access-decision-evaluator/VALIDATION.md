# Validation and interpretation limits

access-policy-checks qualifies Python 3.12/3.13 on Windows and Ubuntu. Required native
fixtures cover read/hash, fresh-file write/readback, hardlink-input refusal, linked-
parent refusal, changed-input detection and overwrite refusal. Only opposite-platform
methods may skip; local volume skips are not native proof.

Known-answer/adversarial tests cover inherited roles, cycles/self cycles, unknown
references, duplicate ID-only declarations, actor/rule alias slots, explicit deny-all
policies, set normalization, strict headers and bounded iterative/actor expansion;
inherited explicit-deny precedence, default-deny actors, exact literal action/resource
IDs, null/mismatched expectations and request/rule scope caps; inherited prohibited
role pairs, same-actor same-resource incompatible action claims, distinct resources,
unassigned actor claims, symmetric pair aliases, missing assignments/events, constraint
scope limits and complete repeated event evidence; equal-header-only scenarios,
changed decisions in either direction, missing/added/changed-scope request records,
failed expectations despite equal denial, policy identity conflict and unrequested
scope limits. Every identity collection checks complete duplicate/conflict/rejected-row
accounting. Shared strict JSON/I/O tests preserve source/no-overwrite/fixed-error rules.

Collection acceptance copies each complete tool independently, verifies source pins,
runs actual CLIs, writes fresh reports, refuses overwrite/source output and checks
raw-input pins, unchanged inputs, fixed errors and absence of action artifacts. Connected
invented HVAC service proposals use exact policy/request pins across all four tools.
Separate game-release and AI/software candidate-policy fixtures contain no assets,
models, credentials or real user data. A public Approval Scope Checker adapter shows
that same-actor review-role coverage can pass its own limited contract while the new
explicit duty constraints flag prohibited roles and workflow claims. Its engine is
not duplicated or imported into the new tools.

Synthetic checks do not establish real identities, genuine assignments/history,
secure policy design, complete scenario coverage, production safety, rights or privacy.
Original private code, policies, schemas, records, customer/user data, paths, credentials,
endpoints and deployment details were not consulted or selected. No authentication,
network probing, account/permission changes, actual approvals or actions occur.
