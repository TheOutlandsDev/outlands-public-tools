# Validation and limits

web-form-checks qualifies Python 3.12/3.13 on Windows/Ubuntu. Required native fixtures
cover ordinary read/hash, fresh write/readback, hardlink refusal, linked-parent refusal,
changed-input detection and overwrite refusal. Only opposite-platform methods may skip.

Known answers and adversarial tests cover DAG dependencies, invalid/absent/hidden parent
conditions, typed rules, hidden values, conditional requiredness, nested identities,
normalized pins, complete row accounting, unknown-field counting/value suppression,
bounded assessments, exact flow/form/submission references, deterministic action slots,
reachable/terminating graphs, invalid-prefix stopping, explicit invalid-submission
branches, partial histories, expectation separation and exact typed scenario equality.
Missing/added/changed observations never become clean comparisons. Visibility changes
are observable even when validity remains equal. Equal expected-negative comparisons
do not imply valid submissions/histories or whole-UI compatibility.

Actual standalone acceptance copies each whole tool, verifies manifests, runs CLIs,
creates fresh reports, refuses overwrite/source output and checks unchanged inputs,
fixed errors and absence of action artifacts. Four connected fictional HVAC CLIs bind
form/submission/flow/history versions. Game-form and AI/software submission examples
are invented. An explicit collection-only scalar projection exercises the existing
public Configuration Contract Checker, including out-of-range rejection; its engine
is not duplicated/imported and it does not establish conditional UI behavior.

This pass checks custom declarations and supplied histories. It does not open a browser,
inspect a DOM, render forms, execute scripts, send submissions, contact services, verify
people/permissions or establish HTML conformance, accessibility, security, privacy or
real application behavior. Original implementations, real forms/rules, user/customer
records, private paths, credentials, deployment and operational data were not consulted
or selected. Live browser validation is a separate evidence requirement.
